## 1. 작업 순서별 확인 (첫 주문 때 한 번씩)
| 순서 | 누가 | 확인할 것 |
|---|---|---|
| 주문 입력 | 형 | 한 줄 입력→미리보기→확정. 확정 후 주문 목록에 **고객명과 상품이 같이** 보이는지. 오류가 나면 화면의 문구를 그대로 사진으로 남긴다. |
| 박스 할당 | 어머니 | 제출하면 다음 업체로 넘어가는지. "박스 추가"는 제출 버튼 왼쪽의 큰 버튼. |
| 일괄 출력 | 어머니 | 박스를 제출한 업체만 출력(택배 제외). 출력 후 목록의 라벨 현황이 바뀌는지. 프린터 PC 확인(감열 라벨지 여부). |
| 주문 목록 | 현장 | **칠판이 까맣지 않고 주문이 보이는지**(#172 수정 후 현장 확인됨). 펜 필기·포장 완료. |
| 상차 스캔 | 아버지 등 | 한 박스 스캔→"상차됨". 박스가 남은 업체는 "이 업체 상차 완료"가 안 뜬다(예: 1/2). |

## 2. 문제가 났을 때
| 증상 | 먼저 할 일 |
|---|---|
| 확정이 실패하고 빨간 문구가 뜸 | 문구를 사진으로 남기고, 화면에 안내된 대로 한다. "저장하지 않았습니다"면 같은 글을 다시 확정, "새 상품은 저장됐지만…"이면 **다시 확정하지 말고** 주문 목록에서 확인. |
| 연결이 끊겼다는 안내 | 미리보기가 서버 기준으로 다시 열린다. "변경 없음"으로 보이는 줄은 이미 저장된 것이니 남은 것만 확정. |
| 고객사만 보이고 상품이 없음 | 같은 글을 미리보기부터 다시. 계속되면 사진과 함께 알린다. |
| 칠판 화면이 까맣거나 멈춤 | 새로고침. 계속되면 PC로 같은 주소를 열어 PC 화면은 정상인지 확인하고 알린다. |
| 라벨이 안 나옴/상차 스캔이 "출력된 적 없는 번호" | 라벨 출력 상태(목록의 라벨 현황) 확인 후 해당 업체만 단일 재출력. 번호는 재출력해도 같다. |
| 서비스 전체가 이상함(배포 직후) | Vercel → Deployments에서 직전 정상 배포를 **Instant Rollback**(Promote to Production)한다. DB 변경은 되돌려지지 않으므로 마이그레이션은 되돌리지 않는다. |

## 3. 알려진 한계 (고치지 않음, P2)
- 박스 할당 화면은 실시간 갱신이 없다(다른 기기 변경은 새로고침해야 보임). 같은 업체를 두 사람이 동시에 제출하지 않는다.

- 박스가 상품 수보다 많으면 자동 배정이 마지막 박스에 몰아 제출이 막힌다(박스를 줄인다).
