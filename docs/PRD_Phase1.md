# PRD: B2B 수산물 유통 업무 자동화 시스템 — 1단계

**문서 버전**: v1.3  
**작성일**: 2026-04-04  
**작성자**: Antigravity AI  
**프로젝트 코드명**: FishBoard

---

## 1. 개요 (Overview)

### 1.1 배경 및 문제 정의

경남 통영 기반 B2B 수산물 유통 업체로, 매일 경매/매입한 신선 수산물을 호텔·오마카세·이자카야 등 외식 사업장에 고속버스 택배와 퀵 서비스를 통해 당일 배송한다.

현재 워크플로우의 핵심 문제점:

| 문제 | 영향 |
|------|------|
| 주문 내용을 손으로 화이트보드에 옮겨적음 | 작업 시간 낭비, 오기입 리스크 |
| 주문 추가/수정 시 화이트보드 재작성 | 반복 작업, 혼선 발생 |
| 습식 현장 환경 (장갑 착탈) | 핸드폰·펜 사용 불편 |
| 화이트보드 지워짐 | 주문 누락 및 오배송 |

### 1.2 솔루션 요약

카카오톡으로 전달된 주문 메세지를 텍스트로 붙여넣으면 자동으로 **상품 요약 대시보드**와 **업체별 주문 목록**을 생성·표시하는 웹 기반 현장 관리 시스템을 구축한다. 시스템은 클라우드에 배포되어 영업 담당자는 통영 현장 외부에서도 온라인으로 접근할 수 있으며, 역할에 따른 계정 로그인으로 접근 권한이 관리된다.

### 1.3 목표 사용자

| 역할 | 위치 | 설명 |
|------|------|------|
| **영업 담당자** | 원격 (통영 외부) | 주문 취합 후 시스템에 직접 입력 또는 카카오톡 메세지 붙여넣기. 어디서든 온라인 접근 |
| **현장 담당자 (관리자)** | 통영 현장 | 주문 입력·수정, 설정 관리, 주문 현황 전체 관리 |
| **현장 작업자** | 통영 현장 | 모니터 화면 확인, 포장 완료 처리, 중량 입력 |

### 1.4 배포 환경

**현장 (통영)**
- 대형 모니터 2대 (키오스크 모드 또는 전체 화면 브라우저)
  - **모니터 1**: 화면 상단 — 상품별 총 수량 요약 / 화면 하단 — 업체별 주문 목록
  - **모니터 2**: 화면 전체 — 업체별 주문 목록 (작업자 참조용)
- 관리자용 입력 PC / 태블릿 1대

**원격 (영업 담당자)**
- 인터넷 브라우저로 어디서든 접근 가능 (스마트폰, 태블릿, 노트북)
- 로그인 후 주문 입력 및 현황 조회 가능

**인프라**
- 클라우드 서버에 배포 (예: Vercel, Railway, Fly.io)
- 클라우드 DB 사용으로 실시간 데이터 동기화
- HTTPS 필수 (보안 전송)

## 2. 범위 (Scope)

### ✅ 1단계 포함 기능

1. 카카오톡 메세지 텍스트 파싱 및 주문 자동 생성
2. 상품별 총 수량 요약 (모니터 1 상단)
3. 업체별 주문 목록 (모니터 1 하단 + 모니터 2 전체)
4. 역할 기반 계정 인증 (영업 담당자 / 현장 담당자 / 작업자)
5. 클라우드 배포 및 온라인 접근
6. 업체–터미널 매핑 관리
7. 박스 규격 및 상품 규격 관리
8. 자동 박스 배분(packing) 알고리즘
9. 물봉(물봉박스) 처리
10. 주문 변경 시 시각적 하이라이트 알림
11. 포장 완료 처리 (업체별 / 상품별)
12. 중량 입력 기능 (셀 단위)

### ❌ 1단계 제외 기능 (2단계 이후)

- 카카오톡 채팅방 직접 연동 및 자동 파싱
- 스마트워치/헤드셋 음성 명령 처리

## 3. 기능 요구사항

### 3.1 주문 입력 — 카카오톡 메세지 파서

#### 3.1.1 메세지 포맷 정의

영업 담당자가 전달하는 카카오톡 메세지의 일반적인 형태:

```
[업체명]
- 상품명 수량
- 상품명 수량 (크기/중량 요청)
- 상품명 수량 (물봉)

[업체명2]
- 상품명 수량
...
```

예시:
```
[제주 오마카세]
- 광어 2마리 (2kg 이상)
- 돔 3마리
- 문어 1kg (물봉)

[부산 이자카야]
- 전복 10개
- 킹크랩 2마리 (3kg)
```

#### 3.1.2 파서 요구사항

- **FR-P-01**: 텍스트 입력창에 메세지를 붙여넣으면 구조화된 주문 데이터로 자동 파싱한다.
- **FR-P-02**: 업체명(`[업체명]` 형식), 상품명, 수량, 단위(마리/개/kg 등)를 추출한다.
- **FR-P-03**: 괄호 내 크기·중량 요청사항을 별도 필드로 저장한다.
- **FR-P-04**: `물봉` 키워드가 포함된 상품은 `is_mulbong: true`로 플래그 처리한다.
- **FR-P-05**: 파싱에 실패하거나 인식 불가한 라인은 별도 경고창에 표시하여 수동 확인을 유도한다.
- **FR-P-06**: 파싱 결과를 확인하는 미리보기(Preview) 화면을 제공하고 사용자가 확인 버튼을 누른 후 적용한다.
- **FR-P-07**: 메세지 재입력 시 기존 주문과 비교하여 **추가/수정/취소** 항목을 판별한다.

#### 3.1.3 수동 편집

- **FR-P-08**: 파싱 후 주문 목록에서 개별 주문 항목을 직접 추가·수정·삭제할 수 있다.
- **FR-P-09**: 주문 항목 수정 시 변경 이력(before/after)이 저장된다.

---

### 3.2 상품별 총 수량 요약 (모니터 1 상단)

- **FR-D-01**: 모니터 1의 **상단 영역**에 전체 주문에서 상품별 총 수량을 집계하여 가로형 카드 형태로 표시한다.
- **FR-D-02**: 각 카드에는 상품명, 총 수량, 단위가 크고 명확하게 표시된다.
- **FR-D-03**: 물봉 수량은 일반 수량과 구분하여 함께 표시한다. (예: `광어 5마리 / 물봉 2마리`)
- **FR-D-04**: 포장 완료된 수량 / 전체 수량을 진행률 바(progress bar)로 표시한다.
- **FR-D-05**: 주문 변경으로 수량이 달라진 상품 카드는 시각적으로 하이라이트(노란색 또는 오렌지 테두리)된다.
- **FR-D-06**: 요약 영역은 자동으로 최신 데이터를 반영한다 (실시간 업데이트, 새로고침 불필요).
- **FR-D-07**: 상품 카드는 총 수량 기준 내림차순으로 정렬된다.
- **FR-D-08**: 요약 영역 우측에 최종 업데이트 시각 및 오늘 날짜를 표시한다.
- **FR-D-09**: 상단 요약 영역의 높이는 전체 화면의 약 25~30%를 차지하며, 나머지 하단에 주문 목록이 표시된다.

### 3.3 주문 목록 — 업체별 주문 현황 (모니터 1 하단 + 모니터 2 전체)

#### 3.3.1 기본 표시

- **FR-O-01**: 주문 목록은 **모니터 1 하단**과 **모니터 2 전체 화면** 모두에 동일하게 표시된다. 두 화면은 동일한 데이터를 실시간으로 공유한다.
- **FR-O-02**: 업체별로 행을 구성하고, 컬럼은 다음을 포함한다:
  - 업체명
  - 터미널명 (업체-터미널 매핑 기반 자동 표시)
  - 상품별 수량 (각 상품이 동적 컬럼으로 생성)
  - 특이사항/요청 (크기, 중량 요청)
  - 박스 배분 결과
  - 포장 완료 상태

- **FR-O-03**: 크기·중량 요청이 있는 셀에는 요청사항이 별도 태그 또는 서브텍스트로 표시된다.
- **FR-O-04**: 물봉 상품은 해당 셀 또는 박스 표시에 `물봉` 배지(badge)로 구분된다.
- **FR-O-05**: 포장 완료된 셀은 배경색(연한 녹색) 또는 체크 아이콘으로 시각적으로 구분된다.
- **FR-O-06**: 업체 행 전체가 완료되면 행 전체에 완료 스타일(취소선 또는 녹색 배경)을 적용한다.

#### 3.3.2 주문 변경 알림

- **FR-O-07**: 새로 추가된 업체 행은 **초록색 테두리** 또는 `NEW` 배지로 표시한다.
- **FR-O-08**: 기존 주문에서 수정된 셀(수량 변경, 상품 추가)은 **노란색 배경**으로 하이라이트한다.
- **FR-O-09**: 취소된 항목은 **빨간색 취소선**으로 표시한다.
- **FR-O-10**: 변경 알림 표시는 작업자가 확인('확인' 버튼 또는 클릭)하면 해제할 수 있다.

#### 3.3.3 중량 입력

- **FR-O-11**: 중량 요청이 있는 상품 셀을 클릭하면 인라인 또는 팝업으로 실제 포장 중량을 입력할 수 있다.
- **FR-O-12**: 입력된 중량은 해당 셀에 표시되고, 요청 중량 대비 초과/부족 여부를 색상으로 나타낸다.

#### 3.3.4 포장 완료 처리

- **FR-O-13**: 개별 상품·업체 셀(교차점)을 클릭(또는 더블클릭)하면 포장 완료/미완료 상태를 토글할 수 있다.
- **FR-O-14**: 업체 행 전체 완료는 행 우측 또는 하단의 '업체 전체 완료' 버튼으로 일괄 처리할 수 있다.
- **FR-O-15**: 완료 처리 시 완료 시각이 기록된다.

### 3.4 사용자 인증 및 접근 권한

#### 3.4.1 인증 방식

- **FR-A-01**: 이메일 + 비밀번호 기반 로그인을 지원한다.
- **FR-A-02**: 로그인하지 않은 사용자는 주문 데이터에 접근할 수 없으며, 로그인 페이지로 리다이렉트된다.
- **FR-A-03**: 세션은 일정 시간(예: 24시간) 유지되며, 이후 재로그인이 필요하다.
- **FR-A-04**: 현장 모니터(키오스크)는 별도 「현장 뷰 전용 계정」으로 장기 로그인 상태를 유지할 수 있다.

#### 3.4.2 역할 및 권한

| 역할 | 권한 |
|------|------|
| **관리자 (Admin)** | 전체 기능 접근. 주문 입력·수정·삭제, 설정 관리, 사용자 계정 관리 |
| **영업 담당자 (Sales)** | 주문 입력·수정, 주문 현황 조회. 설정 관리 불가 |
| **현장 작업자 (Worker)** | 주문 현황 조회, 포장 완료 처리, 중량 입력. 주문 생성·삭제 불가 |
| **뷰어 (Viewer)** | 현장 모니터 전용. 주문 현황 조회만 가능 (읽기 전용) |

- **FR-A-05**: 관리자는 사용자 계정을 생성·수정·비활성화할 수 있다.
- **FR-A-06**: 각 계정에 역할을 지정하며, 역할에 따라 UI 메뉴 및 버튼이 동적으로 표시/숨김 처리된다.
- **FR-A-07**: 권한 외의 API 엔드포인트 접근 시 403 에러를 반환한다.

---

### 3.5 업체–터미널 매핑 관리

- **FR-T-01**: 관리자 또는 현장 담당자가 설정 화면에서 업체명과 터미널명을 매핑하여 등록·수정·삭제할 수 있다.
- **FR-T-02**: 주문 파싱 시 업체명이 매핑 목록에 존재하면 자동으로 터미널명이 할당된다.
- **FR-T-03**: 매핑에 없는 업체가 파싱되면 경고를 표시하고 터미널을 수동으로 선택할 수 있다.
- **FR-T-04**: 터미널 목록(예: 서울고속버스터미널, 부산종합터미널 등)도 관리자가 관리할 수 있다.
- **FR-T-05**: 업체 정보에는 기본 메모(예: 단골 특이사항, 선호 포장 방식)를 추가할 수 있다.

---

### 3.6 박스 규격 및 상품 규격 관리

#### 3.6.1 박스 규격

- **FR-B-01**: 현장 보유 박스 종류를 관리자/현장 담당자 설정 화면에서 등록·수정·삭제할 수 있다.
- **FR-B-02**: 박스 정보:
  - 박스명 (예: 소형, 중형, 대형, 물봉박스)
  - 유효 내부 치수 (가로 × 세로 × 높이, mm 또는 cm)
  - 실제 적재 가능 부피 (포장재·얼음·아이스팩 점유 공간 차감 후)
  - 얼음/아이스팩 기본 점유 부피 (설정 가능)
  - 포장재(에어캡, 스티로폼 등) 점유 두께 또는 부피 (설정 가능)
  - 물봉 전용 여부 플래그

- **FR-B-03**: 박스별 **유효 적재 가능 부피** = 전체 내부 부피 − 기본 포장재 부피 − 얼음/아이스팩 부피

#### 3.6.2 상품 규격

- **FR-B-04**: 상품별 표준 부피 또는 크기를 관리자 설정 화면에서 등록할 수 있다.
- **FR-B-05**: 상품 정보:
  - 상품명
  - 표준 1단위 부피 (cm³ 또는 추정 부피)
  - 크기 변형 계수 (예: 2kg 이상일 경우 1.5배로 계산)
  - 물봉 가능 여부

### 3.7 박스 자동 배분(Packing) 알고리즘

- **FR-K-01**: 업체별 주문 항목(상품명 + 수량 + 크기/중량 요청)을 기반으로 필요한 박스 조합을 자동 계산한다.
- **FR-K-02**: 알고리즘 목표:
  - 박스 수 최소화
  - 박스 내 잔여 공간(Dead Space) 최소화
  - 총 포장 비용(박스 단가) 최소화 (옵션)

- **FR-K-03**: 알고리즘 입력:
  - 상품별 총 부피 (수량 × 단위 부피 × 크기 계수)
  - 사용 가능한 박스 목록 (규격별 유효 적재 부피)

- **FR-K-04**: 알고리즘 출력:
  - 박스 종류 및 수량 (예: 중형 2개, 소형 1개)
  - 각 박스에 담기는 상품 목록
  - 잔여 공간 비율 (%)

- **FR-K-05**: 물봉 주문 항목은 물봉박스에 우선 배분되며, 물봉박스는 물봉 전용으로만 사용된다.
- **FR-K-06**: 배분 결과는 주문 목록의 해당 행에 요약 형태(`중형×2 + 소형×1`)로 표시된다.
- **FR-K-07**: 현장 담당자가 배분 결과를 수동으로 수정할 수 있다 (override).
- **FR-K-08**: 잔여 공간이 설정 임계값(예: 30%) 이상인 박스는 경고 색상으로 표시한다.

## 7. 카카오톡 메세지 파싱 규칙 상세

> 실제 운영 메세지 40건 분석을 통해 확정된 포맷입니다. 상세 가이드: `docs/kakao-message-format-guide.md`

### 7.1 확정 메세지 포맷

```
[번호] [터미널]/ [업체명]/ [상품1], [상품2], ...
```

**실제 예시:**
```
1 대구/ 스시아타이/ 활전갱이 3미, 일산중방어 1마리(5-6kg)
6 해운대/ 스시이루카/ 활전갱이 8마리, 일산참돔 2미, 양식광어 1미, 시마아지 1미, 벤자리 3미
9 해운대/ 스시미우라/ 활전갱이 2미, 감성돔 1미+2.5키로, 시마아지 1미, 벤자리 2미
19 남부/ 히노츠키/ 활전갱이 3.5키로, 말쥐치 2키로, 붉바리 2마리, 갯가재 1키로, 활장어 2키로(키로5-6미급, 기포기)
25 남부/ 하시라/ 활전갱이 18미, 자연산 전복 4키로(300이상), 돌문어 4마리(2kg이상, 물봉 2박스), 벤자리 2미
```

### 7.2 구성 요소 및 파싱 규칙

| 요소 | 규칙 | 예시 |
|------|------|------|
| **번호** | 라인 시작 숫자 | `1`, `25` |
| **터미널** | 첫 번째 `/` 이전 텍스트 | `대구`, `남부`, `해운대` |
| **업체명** | 두 번째 `/` 이전 텍스트 | `스시아타이`, `신라호텔` |
| **상품 목록** | 두 번째 `/` 이후, `,`로 구분 | `활전갱이 3미, 일산참돔 1미` |
| **상품명** | 수량 앞의 텍스트 | `활전갱이`, `자연산 전복` |
| **수량** | `숫자 + 단위` | `3미`, `2키로`, `5팩` |
| **요청사항** | 마지막 `(괄호)` 내용 | `(큰거)`, `(300이상, 물봉)` |

### 7.3 수량 단위 표준

| 단위 표기 | 정규화 | 타입 |
|----------|--------|------|
| `미`, `마리` | `마리` | 개체 수 |
| `키로`, `kg` | `kg` | 중량 |
| `팩` | `팩` | 팩 수 |
| `개` | `개` | 개 수 |

### 7.4 핵심 파싱 규칙 2가지

**규칙 1 — 마리수 + 중량 병기 시 `+`로 구분:**
```
✅ 감성돔 1미+2.5키로  →  quantity: 1마리, weight: 2.5kg
✅ 자연산 전복 6미+1키로
❌ 감성돔 1미2.5키로   (파싱 오류 — 구분자 필요)
```

**규칙 2 — 포장 특이사항은 항상 마지막 괄호 하나에:**
```
✅ 돌문어 4마리(2kg이상, 물봉)         → size_request: "2kg이상", is_mulbong: true
✅ 활장어 2키로(키로5-6미급, 기포기)   → size_request: "키로5-6미급", is_mulbong: true
❌ 돌문어(2kg이상) 4마리(물봉)         (괄호 2개 — 파싱 오류)
```

### 7.5 포장 키워드 인식

| 괄호 내 키워드 | 시스템 처리 |
|--------------|------------|
| `물봉`, `물봉 N박스` | `is_mulbong: true`, 물봉박스 배정 |
| `기포기` | `is_mulbong: true`, 물봉박스 배정 (동일) |
| `얼음포장` | `special_packaging: "얼음포장"`, 일반박스 + 메모 |
| `재고` | `from_stock: true` |
| 그 외 | `size_request` 필드에 저장 |

### 7.6 파싱 오류 처리

| 케이스 | 처리 방법 |
|--------|----------|
| 터미널 미등록 | 경고 표시 후 수동 선택 |
| 업체명 신규 | 경고 표시 후 터미널 수동 매핑 |
| 단위 미인식 | 기본 단위 `개` 적용 후 사용자 확인 |
| `+` 없는 수량+중량 | 경고 표시, 수동 분리 입력 요청 |
| 괄호 2개 이상 | 경고 표시, 수동 수정 요청 |

## 8. 박스 배분 알고리즘 상세

### 8.1 알고리즘 접근법

**휴리스틱 Bin Packing (FFD 변형)**:
1. 상품 항목을 부피 내림차순으로 정렬
2. 물봉 항목은 먼저 분리하여 물봉박스에 배분
3. 나머지 항목에 대해 가장 공간이 적게 남는 박스부터 채우는 **Best Fit Decreasing(BFD)** 적용
4. 현재 박스에 들어가지 않으면 새 박스 개시

### 8.2 계산 순서

```
1. 업체별 주문 항목 로드
2. 각 상품의 실제 부피 계산
   → 단위 부피 × 수량 × 크기 계수(size_request에 따라)
3. 물봉 항목 분리
4. 물봉 항목 → 물봉박스 배분
5. 일반 항목 → BFD 알고리즘으로 박스 배분
6. 각 박스의 잔여 공간 % 계산
7. 결과 저장 및 화면 표시
```

### 8.3 예외 처리

- 단일 상품이 가장 큰 박스보다 클 경우: 경고 표시 및 수동 처리 요청
- 박스 재고 부족: 현재 단계에서는 재고 개념 없음, 추후 확장 가능

| **배포 방식** | 클라우드 배포 (Vercel + 클라우드 DB). 인터넷으로 어디서든 접근 |
| **사용자 인증** | 역할 기반 계정 로그인 필수 (관리자 / 영업 / 작업자 / 뷰어) |
| **메세지 포맷** | `[번호] [터미널]/ [업체]/ [상품목록]` 구조 확정. `+` 수량+중량 구분, 마지막 괄호 포장 규칙 적용 |
| **데이터 영속성** | 날짜별 이력 전체 보관. 정산·AI 튜닝·시즌별 분석·업체별 주문현황 조회 목적 |
| **주문 리셋** | 매일 자동으로 새 영업일 세션 시작. 전날 데이터는 아카이빙 (삭제 없음) |

## 13. 데이터 이력 및 분석 요구사항

### 13.1 데이터 보관 정책

- **FR-H-01**: 모든 주문 데이터는 영업일(날짜) 단위로 영구 보관한다. 삭제하지 않는다.
- **FR-H-02**: 매일 영업 시작 시 새 영업일 세션이 자동 생성된다 (자정 또는 관리자 수동 시작).
- **FR-H-03**: 전날 완료된 주문 데이터는 자동으로 아카이빙 상태로 전환되며, 현장 모니터에서는 당일 데이터만 표시된다.
- **FR-H-04**: 아카이빙된 데이터는 관리자/영업 담당자가 날짜를 선택하여 조회할 수 있다.

### 13.2 이력 데이터 활용 목적

| 목적 | 설명 |
|------|------|
| **업체 정산** | 날짜별·업체별 주문 내역을 기반으로 정산 자료 조회 및 출력 |
| **AI 파서 튜닝** | 축적된 메세지-주문 페어 데이터로 파싱 정확도 지속 개선 (2단계) |
| **시즌별 주문 추이** | 월별·분기별 상품 수요 변화 파악, 매입 계획 수립 지원 |
| **업체별 주문 현황** | 업체별 주문 빈도, 선호 상품, 평균 주문량 분석 |

### 13.3 1단계 분석 기능 (기본)

- **FR-H-05**: 날짜 범위를 지정해 기간 내 전체 주문 목록을 조회할 수 있다.
- **FR-H-06**: 업체별로 필터링하여 해당 업체의 주문 이력을 조회할 수 있다.
- **FR-H-07**: 날짜별 주문 요약 (총 업체 수, 총 상품 종류, 포장 완료 여부)을 리스트로 확인할 수 있다.

### 13.4 2단계 분석 기능 (고도화, 추후)

- 상품별 시즌 추이 차트
- 업체별 주문 빈도 분석
- 이력 데이터 기반 AI 파싱 모델 파인튜닝
- 정산서 자동 생성 및 내보내기 (Excel / PDF)
