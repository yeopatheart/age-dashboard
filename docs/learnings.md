# 배운 것

출처와 날짜를 함께 적는다.

- **유포지는 소재, 감열은 인쇄 방식이다. 둘 다 있다.** 유포지에 감열 코팅을 한 "감열 유포 라벨"과 코팅 없는 열전사용 유포지가 따로 팔린다. 상품명에 "유포지"만 있고 "감열"이 없으면 열전사용일 수 있다. (출처: 4B-2054L 사양표 "유포 감열 라벨", kookjincom 상품 페이지, nowfix 상품 페이지, 2026-11-12)
- **4B-2054L은 감열 전용이라 리본을 못 쓴다.** (출처: 제품 사양표, 매뉴얼 manualslib 29쪽, 2026-11-12)
- **smartstore.naver.com은 AI 도구로 열 수 없다.** 내장 브라우저, WebFetch, Claude in Chrome(연결된 상태)이 모두 "안전 제한"으로 막혔다. 상품 정보는 사용자 캡처로 받는다. (출처: 도구 오류, 2026-11-12)
- **스마트스토어 "평균 2일 이내 도착"은 영업일 기준이다.** 주말·공휴일이 빠져서, 금요일 발송분이 토요일에 오는지는 판매자에게 물어야 한다. (출처: kookjincom 상품 페이지 배송 표기, 2026-11-12)
- **지관 "40지관"은 내경 약 40mm이다.** 상품 표기 "지관내경 4cm"와 일치한다. 롤 받침 부품이 맞는지는 개봉해서 확인해야 한다. (출처: kookjincom 상품 페이지, 2026-11-12)
- **개발 서버(`age-dashboard-dev`)는 운영 Supabase에 연결돼 있다.** 읽기 화면은 확인할 수 있지만 포장·수량·제출·일괄 출력 같은 쓰기는 눌러 볼 수 없어서 단위 테스트와 "눌러 본 것/못 본 것" 구분 보고가 필요하다. 테스트 Supabase 키는 로컬에 없다(`.env.local`을 받아야 함). (출처: 이번 세션 전반, `.local-data/test-env` 확인, 2026-11-14)
- **브라우저 창의 로그인이 풀리면 `/login`으로 간다.** 비밀번호는 입력할 수 없으니 사용자에게 로그인을 요청하고, 그동안 브라우저가 필요 없는 검증·문서를 끝낸다. (출처: 박스 할당 3단계 화면 확인 때, 2026-11-14)
- **백그라운드 탭은 React 렌더가 밀려 시험이 어긋난다.** 새 탭(`tabs_create`)은 숨겨진 채 폭이 모바일 크기로 열려 펜 버튼 같은 하이드레이션 뒤 UI가 안 나타났다. 화면 시험은 앞 탭에서 하고, 클릭 스크립트는 상태 반영을 기다리는 대기(≥200ms)를 넣는다. (출처: 펜 PC 동기화 시험·합포장 시험, 2026-11-14)
- **숨겨 둔 채 높이를 재는 행은 보이는 행과 모양이 같아야 한다.** 별도 주문 팝업에서 숨긴 행만 드래그 손잡이를 뺐더니 칩 영역이 넓어져 높이가 80px → 44px로 다르게 재졌고, 쪽 나눔이 화면에 따라 오락가락해 한 행이 어느 쪽에도 안 나왔다. (출처: 11/13 별도 주문 15건 시험, 2026-11-14)
- **렌더 중 `window`를 읽는 컴포넌트는 서버에서 그리면 오류가 난다.** 펜 그림 층을 `&pen=1`·PC 보기에서 서버 렌더가 켜면 "Switched to client rendering" 오류가 난다 → `useHydrated`·`useTouchDesktop`(서버는 항상 false)로 하이드레이션 뒤에만 그린다. (출처: 개발 서버 로그, 2026-11-14)
- **새 테이블을 기존 실시간 채널에 합치면 마이그레이션 전 배포가 위험하다(가정, 미검증).** 발행에 없는 테이블을 구독하면 채널 전체가 실패할 수 있다고 보고 `board_ink`는 별도 채널로 열었다. 주문 알림 채널과 분리돼 있다. (출처: 구현 판단, 2026-11-14)
- **`npm test`는 `src/lib/*.test.ts`만 돈다.** 하위 폴더(`src/lib/sound/…`)에 테스트를 두면 실행되지 않는다. (출처: package.json `test` 스크립트, 2026-11-14)
- **커밋·푸시는 요청받았을 때만 한다.** 시험 뒤 커밋·푸시를 한 번에 묶어 실행하려다 권한 분류기에 막혔다(사용자 지시가 없었음). 요청을 받은 뒤에만 커밋하고, "커밋"만 말하면 푸시·PR은 따로 묻는다. (출처: 2026-11-14, 첫 번째 사례)
- **Vercel Deployments에서 운영 중인 배포는 파란 `Current` 하나뿐이다.** 여러 행에 "Production"이 붙어 있어도 시계 아이콘이면 빌드만 된 것이다. Instant Rollback 뒤에는 새 배포가 자동 연결되지 않았다(이 프로젝트, Auto-assign 설정은 미확인). 운영 주소 응답(`curl -I`)의 `age`가 새 배포 시각보다 오래되면 옛 배포가 서빙 중이다. (출처: Deployments 화면 캡처, 운영 주소 응답 `age: 13925`, 2026-11-16)
- **Vercel Hobby의 Runtime Logs는 1시간쯤만 남는다.** 장애 직후 바로 복사하지 않으면 사라진다. 오류가 클라이언트 렌더 오류(React)면 서버 로그에는 아무것도 없다. (출처: 로그 조회 시도, 2026-11-16)
- **Next 16.4.5의 `error.tsx`는 `retry`·`reset` prop을 넘긴다. `unstable_retry`는 없다.** (출처: `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`, 재현 오류 `unstable_retry is not a function`, 2026-11-16)
- **오류 화면에 "오류 번호"(digest)가 없으면 서버가 아니라 클라이언트 렌더 오류일 가능성이 크다.** 서버 컴포넌트 오류만 digest를 가진다. 이번에는 별도 주문 팝업의 무한 재렌더(`Maximum update depth exceeded`)였다. (출처: 칠판 오류 사진과 로컬 재현, 2026-11-16)
- **칠판 기기 값**: Linux x86_64 Chrome/157, `maxTouchPoints` 2, 화면·창 1280×720, 배율 3, `pointer: fine=false`, `hover=false`. `/dashboard/pen-test`가 이 값을 화면에 보여 주므로 칠판 앞에 가면 서버 로그 없이 확인할 수 있다. (출처: 칠판 사진, 2026-11-16)
- **같은 세션 토큰을 여러 요청이 동시에 갱신하면 Auth 서버가 409 `conflict`를 준다.** 09:51 KST에 `/dashboard`·`/overview`·`/orders/new`·`/packing-log` 요청이 같은 순간 모두 이 오류로 실패했다(탭·메뉴 미리불러오기 동시 열림 추정). #188에서 일시적 오류로 처리하지만, #184 직후 칠판 펜이 막힌 원인이 이것이었는지는 **증명하지 못했다.** (출처: 운영 로그, 2026-11-16)
- **로컬에서 칠판 펜 동작 재현법(테스트 DB 전용)**: `?monitor=1&pen=1`로 터치 기기처럼 열고, 펜 플로팅 버튼은 **실제 마우스 클릭**으로 켠 뒤(DOM `.click()`으로는 안 켜졌다) 캔버스에 `pointerType: 'pen'` PointerEvent를 보내 동그라미·대각선을 그린다. 별도 주문 카드는 테스트 프로젝트에 service role로 넣고 끝나면 지운다. (출처: #190 재현, 2026-11-16)
- **`<style>` 안 모바일 격자에서 자식이 칸보다 많으면 마지막 칸이 줄 바꿈으로 밀려난다.** 박스 할당 모바일에서 박스 ✕가 칩 아래 구석에 떨어져 있던 이유다. (출처: 박스 할당 화면 재현, 2026-11-16)

- **주문 40건이 모니터 1·2의 한계였다(줄 높이 최소 30px × 줄 수 20 × 2).** 11/16에 모든 기기가 기준 화면(본문 606px)으로 계산하게 되면서 PC의 큰 창에서 보이던 41건 이상도 안 보이게 됐다. 51건 날 "11건 안 보임"으로 드러났다. 이제 80건까지, 줄 높이가 30px 미만이면 `dense` 모양. (출처: `src/lib/monitor-rows.ts`, 장애 2026-11-17, `docs/decisions/2026-11-17-rows-over-40.md`)
- **표 머리줄이 줄바꿈되면 두 모니터의 줄 수 계산이 어긋나 줄이 양쪽에서 사라진다.** 모니터 2는 상품 열이 많아 "상품 N"이 접히면 머리줄이 30→46px로 커지고, 본문 높이가 달라 capacity가 모니터 1과 달라진다. `startIndex`는 자기 capacity를 쓰므로 한 줄이 양쪽에 안 나오고 `hiddenRowCount`도 0이라 배지가 없다. 화면에 보이는 양을 정하는 높이는 변할 수 있는 요소(머리줄)에 의존하게 두지 않는다. (출처: 후속 검증 재현 2026-11-17, 수정 #200)
- **줄 높이를 단계로 고르면 아래 여백이 생기지만, 주문이 늘어도 높이·줄 수가 한동안 같다.** 주문의 절반(올림)으로 꽉 채우면 2건마다 높이가 바뀌어 화면이 계속 움직인다. 사용자가 단계 방식 유지를 택했다. (출처: 51건에서 모니터 2 아래 123px 여백 논의, 2026-11-17)
- **칩에 붙은 필기는 칩과 함께 움직이지만, 줄에 붙은 필기(`row:`)는 줄 폭 비율로 가로 위치가 정해져** 열이 좁아지면 다른 칩 위로 밀릴 수 있다. (출처: G항목 검증 2026-11-17, `src/lib/ink/row-anchor.ts`)
- **검증 중에는 소스를 고치지 않는다. 고칠 게 나오면 검증이 끝난 뒤 후속 커밋·PR로 한다.** 검증 대상과 배포 대상이 어긋나지 않게 하려는 사용자 요구. (출처: 사용자 지적 2026-11-17)
- **계획에서 승인받은 값과 다른 값을 몰래 넣지 않는다.** 주문 확정 메모·사이즈 요청 한도를 승인받은 3000/500자 대신 500/100자로 넣었다가 머지 전에 스스로 발견해 되돌렸다. 카톡 괄호 안 글이 그대로 `sizeRequest`가 되므로 좁은 한도는 새벽 주문 입력 전체를 막을 수 있다. (출처: PR #198 작성 중, 2026-11-16)
- **main에 머지하면 Vercel 운영이 바로 배포된다.** 영업 시작 전후 머지는 사용자가 결정하고, 머지 직후 파란 Current·주문 목록·스캔 1건을 확인한다. (출처: 2026-11-16~17 #198~#200 운영)
- **로컬 개발 서버에서 브라우저 패널 폭이 바뀌면 창 에뮬레이션이 풀려 모바일 레이아웃으로 바뀌고, 돌아와도 줄 높이가 예전 값으로 굳는다(새로고침하면 정상).** 원인 미확인. 칠판 창은 크기가 고정이라 영향이 없을 가능성이 크지만 미확인. (출처: 후속 검증 관찰 2026-11-17)
- **테스트에서 인쇄 버튼을 누르면 실제 print 대화상자가 떠 탭이 멈춘다.** `window.print`·`window.confirm`을 JS로 대체하고 진행한다. (출처: A묶음 검증 2026-11-16)

- **필기 상한(300)에 걸리면 가장 오래된 필기부터 조용히 사라진다.** 11/16·11/17 모니터 1·2 `board_ink`가 모두 정확히 300개였다. 300획의 원본 크기는 약 88KB(획당 약 294바이트)라 1000획이면 약 290KB다. (출처: `board_ink` 조회 2026-11-17)
- **이력으로 "상한 손실"과 "지운 것"을 가르려면 id 순서가 아니라 목록 위치를 본다.** 지우개 조각은 새 id를 달고 원래 위치에 끼워지므로 id 시간으로는 구분이 안 된다. 이력 저장분 A→B 비교에서 A의 맨 앞 연속 빠짐은 상한, 중간 빠짐은 지우개다. (출처: 이력 조회 2026-11-17, `docs/decisions/2026-11-17-ink-recovery-policy.md`)
- **필기 환산에서 열 개수가 달라졌다고 폴백하면 안 된다.** 상품이 추가되면 열은 끝에 늘어나므로 "몇 번째 열의 몇 %"로 환산해야 필기가 칸을 따라간다. 열 수가 같을 때만 환산하면 상품 추가 때 필기가 제자리에 남는다. (출처: 현장 보고 2026-11-17, #209)
- **칠판에서 필기는 `&pen=1` + 모니터 1·2 + 본문이 기준 화면(1248×696)의 높이 ±6%·폭 75~106%일 때만 켜진다.** PC에서도 개발자 도구 기기 모드를 1280×720으로 맞추고 `?monitor=1&pen=1`로 열면 마우스로 칠판 필기를 재현할 수 있다(지난 날짜·테스트 날짜에서). 아이패드는 높이가 커서 대개 확대·축소 화면이 되어 필기가 꺼진다. (출처: 코드 확인 2026-11-17, PC 시험 결과 좋음)
- **새 버전 배포 뒤 오래 열어 둔 PC 화면은 옛 코드로 필기를 그릴 수 있다.** 강력 새로고침으로 바로잡혔다(원인이 옛 번들이었는지 캔버스 해상도 결함이었는지는 미확정). 배포 뒤에는 칠판·PC 모두 강력 새로고침. (출처: 현장 보고 2026-11-17)
- **CSS `transform: scale` 안의 캔버스는 `ResizeObserver`가 배율 변화를 못 잡아 해상도가 옛 크기로 남는다.** 그리기 전에 버퍼가 현재 rect와 맞는지 확인한다(#206). 현장에서 이 결함이 일어났다고 확인한 것은 아니다. (출처: 코드 확인 2026-11-17)
- **서버 액션 요청 본문 기본 한도는 1MB다(`next.config`에 설정 없음).** 필기는 한 모니터 전체를 한 번에 보내므로 획 개수와 별개로 총 크기를 약 700KB로 제한한다. (출처: #207)
- **같은 파일을 고치는 PR을 여러 개 열면 병합 순서에 따라 충돌이 난다.** 올리기 전에 임시 폴더에서 세 브랜치를 합쳐 충돌·테스트를 확인했고(`git merge-tree`나 임시 worktree), 충돌은 import 한 줄과 옮겨진 코드 자리뿐이었다. 병합 순서는 PR을 올릴 때 알린다. (출처: 2026-11-17)
