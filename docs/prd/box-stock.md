# 박스 재고·발주 알림

인터뷰로 확정한 요구사항(2026-11-10). 결정 과정과 선택지는 [결정 로그](../decisions/2026-11-10-box-stock.md).

## 목표
마감 후 **박스 재고를 실사로 기록**하고, 사용량을 자동으로 차감해 재고를 추정한 뒤, 재고가 **발주 기준 이하**로 내려가면 앱에서 알리고 **발주 안내(종류·묶음 수)** 를 만들어 준다.

해결하려는 문제(네 가지 모두):
1. 박스가 모자라는 상황 예방
2. 과다 재고·발주 낭비 줄이기
3. 어머니 눈대중 의존 줄이기(누가 봐도 재고와 발주 시점을 알 수 있게)
4. 발주 업무 간소화(무엇을 몇 묶음 시킬지 계산해 주기)

**성공 지표(하나)**: 실사한 날 중, 박스 종류별 재고가 **일평균 사용량의 2~7일치 범위** 안에 있던 날의 비율. (모자람과 쌓임을 한 숫자로 본다.)
- 목표 값은 **운영 4주 측정 뒤에 정한다**(기준선을 모르는 상태에서 숫자를 정하지 않는다).

## 현재 방식 (바꾸려는 것)
- 재고: 눈으로 센다. 발주: 어머니가 "부족하겠다" 싶을 때 업체에 전화한다.
- 급하게 모자란 일은 자주 있지 않다고 알려져 있다. 즉 지금 방식이 큰 사고 없이 돌아가므로, 이 기능의 가치는 "사고 방지"보다 **낭비 감소와 사람 의존 감소**에 있다.
- 박스는 **한 업체**에서 전부 받는다. 최소 주문 수량은 없고 **묶음**으로 온다. **17:00 이전 주문 시 다음 날 도착**, **일요일은 배송이 없어** 토요일 주문은 월요일에 도착한다.

## 안 만들 것 (Non-goals, 첫 버전)
- 박스 외 자재(테이프·아이스팩 등) 재고
- 박스 단가·재고 금액·발주 비용(정산 매입과도 연결하지 않는다)
- 요일 패턴·행사를 반영한 예측(소진 속도는 최근 영업일 평균으로 단순 계산)
- 파손·불량·샘플 같은 **차이 사유 기록**(차이만 보여 준다)
- 외부 알림(카카오톡·문자 자동 발송), 업체에 주문 자동 전송
- 업체 정보 관리(업체가 한 곳이라 업체 이름 필드를 두지 않는다)

## 사용자 시나리오
1. **마감 후 실사(현장 작업자, 휴대폰)**: 박스 종류별 남은 수량을 입력하고 저장한다. 추정과 크게 다르면 한 번 확인한다.
2. **알림 확인(누구나)**: 대시보드와 박스 재고 화면 위에 "물봉 발주 필요 — 17:00 전에 주문하면 내일 도착" 같은 알림이 뜬다. 마지막 실사가 2일 이상 전이면 "실사 필요"가 먼저 뜬다.
3. **발주(어머니를 포함한 현장 작업자)**: 발주 안내를 열어 "물봉 3묶음, 선어박스 2묶음" 같은 글을 복사·공유해 업체에 전화하고, 주문한 뒤 앱에서 **발주 완료**(종류·묶음 수)를 누른다. 알림은 도착 예정분을 포함해서 다시 계산하므로 중복으로 뜨지 않는다.
4. **입고(현장 작업자)**: 박스가 도착하면 종류별 **입고**(묶음 수)를 입력한다. 재고에 바로 반영되고, 발주 수량과 입고 수량이 비교되어 이력에 남는다.
5. **확인(master)**: 박스 리포트에서 재고 일수 추이와 성공 지표(적정 범위 비율)를 본다.

## 요구사항

### 데이터
- **실사 기록**: 일자, 박스 종류, 남은 수량(장), 입력자, 입력 시각. 같은 날 같은 종류를 다시 입력하면 **마지막 값이 현재 값**이고 이전 값은 이력으로 남는다.
- **발주 기록**: 발주 시각, 박스 종류, 묶음 수, 입력자.
- **입고 기록**: 입고 시각, 박스 종류, 묶음 수(장 수로 환산해 재고에 더함), 입력자. 어떤 발주에 대한 입고인지 연결해 **발주 수량 대비 입고 수량**을 볼 수 있다.
- 실사·발주·입고는 **수정·삭제할 수 있고**, 바꾼 사람과 시각이 이력으로 남는다.
- **설정값**: 박스 종류별 묶음당 장수, 알림 기준 일수(기본 2), 확보 일수(기본 5), 소진 속도 평균 영업일 수(기본 14), 주문 마감 시각(기본 17:00), 휴무일 목록. 설정 변경은 master만 한다.

### 계산
- **추정 재고(장)** = 마지막 실사 수량 + 그 이후 입고 − 그 이후 **제출된 박스 수**(박스 할당 제출 기록 기준). 박스 할당을 **재제출하거나 삭제해도 매번 다시 계산**해서 이중으로 빼지 않는다. 새 박스 종류는 첫 실사부터 재고가 잡히고, 비활성 박스는 제외한다.
- **하루 소진 속도(종류별)** = 최근 **14영업일** 평균 사용량. **영업일 = 박스가 한 개라도 제출된 날**(박스 리포트와 같은 기준). 영업일이 14일보다 적으면 있는 만큼으로 계산하고 "데이터 부족"을 표시한다.
- **재고 일수** = (추정 재고 + 도착 예정) ÷ 하루 소진 속도. **도착 예정** = 발주했지만 아직 입고되지 않은 수량.
- **발주 필요(알림)**: 재고 일수가 **알림 기준 일수 이하**이면 알린다. 기준은 기본 2일치이고 **휴무일이 발주·도착 사이에 끼면 그만큼 늘린다**(일요일은 항상 휴무로 자동 반영, 명절·업체 휴무는 설정에서 날짜로 입력). 예: 월~목요일 저녁 2일치, 금·토요일 저녁은 일요일이 끼어 3일치 — 정확한 규칙은 계획 단계에서 단위 테스트로 고정한다.
- **발주 수량 제안** = (확보 일수 × 하루 소진 속도) − (추정 재고 + 도착 예정)를 **묶음 단위로 올림**한다. 값이 0 이하이면 제안하지 않는다.
- **성공 지표** = 실사한 날 중 종류별 재고 일수가 2~7일치 범위인 날의 비율(종류×날짜 단위로 센다).

### 화면 (휴대폰 우선, 기존 모바일 UI 규칙 사용)
- **박스 재고**(새 메뉴): 종류별 카드 — 추정 재고, 재고 일수, 상태(발주 필요/적정/과다), 마지막 실사 시각. 카드에서 **실사 입력**, **입고 입력**, **발주 완료 입력**. 상태는 색만으로 구분하지 않고 글·아이콘을 함께 쓴다.
- **알림**: 대시보드 상단과 박스 재고 화면 상단 배너. 주문 마감 시각과 "다음 날 도착" 문구를 함께 보여 준다.
- **발주 안내**: 부족한 종류와 권장 묶음 수를 글로 만들어 **복사·공유**(기존 공유 방식 재사용). 앱 안에서 업체로 자동 전송하지 않는다.
- **실사 입력 확인**: 입력값이 추정과 **그 종류 하루 평균 사용량 이상 차이**가 나면 "추정 120장, 입력 12장 — 맞나요?"를 한 번 묻고, 맞다고 하면 저장한다(입력은 막지 않는다).
- **설정**(master): 위 설정값 편집.
- **박스 리포트 연동**: 재고 일수 추이와 성공 지표를 박스 리포트에 더한다.

### 권한
- 새 메뉴에 보기·입력 권한을 두고, **어머니를 포함한 현장 작업자 계정**에 부여한다. 설정 변경은 master만 한다. (구체적인 권한 키는 계획 단계에서 정한다.)

## 엣지 케이스와 실패 시 동작
- **실사를 못 한 날**: 알림은 추정 재고로 계속 계산하고 "마지막 실사 N일 전"을 표시한다. 2일 이상이면 알림 위에 "실사 필요"를 띄운다.
- **휴무·일요일**: 실사는 영업일 마감 후에만 요구한다. 소진 속도는 영업일만 센다.
- **두 명이 같은 날 같은 종류 입력**: 마지막 저장값이 현재 값, 이전 값은 이력.
- **잘못 입력한 값**: 수정·삭제 가능, 이력 유지.
- **실사값이 추정과 크게 다름**: 확인 후 저장(위 참조).
- **추정 재고가 음수**: 입고 입력이 빠졌을 가능성이 크므로 음수로 두지 않고 "입고 확인 필요"로 표시하고 알림은 "실사 필요"로 처리한다.
- **첫 사용**: 첫 실사 전에는 알림을 내지 않고 "첫 실사를 입력하세요"만 보여 준다.
- **네트워크가 끊겨 저장이 실패**: 입력값을 지우지 않고 실패했다고 알려 다시 시도하게 한다.
- **박스 할당 재제출·삭제**: 사용량을 매번 다시 계산하므로 재고가 되살아나거나 이중 차감되지 않는다.
- **마이그레이션이 아직 없을 때**: 화면이 죽지 않고 필요한 마이그레이션을 안내한다(프로젝트 규칙).

## 완료 기준
- [ ] 현장 작업자가 휴대폰으로 마감 후 6종 실사를 입력할 수 있다(추정과 크게 다르면 한 번 확인).
- [ ] 입고·발주 완료를 입력하면 재고와 도착 예정이 즉시 계산에 반영되고, 발주 수량 대비 입고 수량이 이력에 남는다.
- [ ] 추정 재고·재고 일수·상태가 박스 재고 화면에 보이고, 발주 필요 알림이 대시보드와 재고 화면에 뜬다.
- [ ] 발주 안내 글(종류별 묶음 수)을 복사·공유할 수 있다.
- [ ] 휴무일(일요일 자동, 설정한 날짜)이 알림 기준과 소진 속도에 반영된다(단위 테스트).
- [ ] 박스 할당 재제출·삭제가 재고를 이중으로 바꾸지 않는다(단위 테스트).
- [ ] 박스 리포트에서 재고 일수 추이와 성공 지표를 볼 수 있다.
- [ ] 실사·발주·입고를 수정·삭제할 수 있고 이력이 남는다.
- [ ] 마이그레이션 적용 전에도 화면이 죽지 않는다.

## 미결 질문
- **박스 종류별 묶음당 장수**: 사용자가 어머니께 확인한 뒤 알려 주기로 했다(2026-11-11 예정). **발주 안내와 묶음 환산 구현은 이 값이 정해진 뒤에 시작한다.** (실사·입고·재고 계산은 장 단위라 값 없이도 시작할 수 있다.)
- **확보 일수(기본 5일치)에도 휴무일 지연을 더할지**: 알림 기준에는 더하기로 정했지만 확보 일수는 정하지 않았다. 계획 단계에서 확인한다.
- **성공 지표 목표 값**: 운영 4주 측정 뒤에 정한다.
- 현장 작업자 계정의 정확한 목록과 권한 키 구성(계획 단계).
- 박스 리포트 연동의 상세(재고 일수 추이의 모양)는 구현 시 정한다.
