# 정산 (settlement)

> 2026-11-07: 영수증 목록은 별도 메뉴 "영수증"(`/receipts`)으로 분리했다(`docs/decisions/2026-11-07-receipts-menu.md`). 영수증 만들기는 이 화면의 판매내역에서 한다.

출고가 끝난 주문을 판매내역·매입내역으로 정리하고 일·주·월 단위로 매입·판매·수익 추이를 본다. 요구사항은 2026-11-06 사용자 요청이고, 설계 결정은 `docs/decisions/2026-11-06-settlement.md`에 있다.

## 해석(사용자와 확인한 것)
- **사업자 = 우리 쪽 사업자등록**이다. 판매·매입 건을 어느 사업자 명의로 처리하는지 구분하는 값이고, 고객사(`businesses`, 이미 `business_registration_no`·`representative_name` 열이 있다)와 별개다.
- **판매가 = 그 줄의 총액(원)**이다(단가 아님). 숫자만 입력하면 콤마가 자동으로 붙는다. 저장은 정수 원.
- **번호**는 화면 순번이고 저장하지 않는다.
- 출고 수량 = 주문 수량 − 미출고 수량. 취소된 줄, 수량 미정 줄, 출고 수량 0인 줄은 판매내역에서 뺀다.
- 매입내역의 "입금 여부"는 우리가 매입처에 지급한 것이지만 요청대로 "입금 여부"로 표기한다.

## 요구사항
### 필터
1. 오늘이 기본이다.
2. 일·주·월 단위로 조회하고, 단위별로 이전/이후로 이동한다(`src/lib/report.ts`의 `getPeriod`·`shiftAnchor` 재사용, 년은 쓰지 않는다).

### 판매내역
- 열: 번호, 사업자 구분, 고객명, 품목, 수량+단위, 판매가, 입금여부, 메모. 주·월 조회에서는 출고일 열을 더한다.
- 품목·수량·단위는 주문 목록 값을 가져오되 정산에서 고칠 수 있다(2026-11-07). 고친 값은 `settlement_sales`의 `*_override`에만 저장하고 주문 목록 원본은 그대로 둔다. 고친 줄은 노란 칸과 ↺(원래대로) 버튼으로 표시하며, 매입내역·영수증·그래프는 고친 값을 따른다. 결정은 `docs/decisions/2026-11-07-settlement-sales-edit.md`.
- 사업자 구분은 드롭다운. 행을 선택해 사업자 구분을 일괄 적용한다.
- 판매가는 사용자가 입력하고 숫자만 받아 콤마로 자동 변환한다.
- 입금 여부는 Y/N 드롭다운(기본 N). 행을 선택해 일괄 적용한다.
- 메모는 텍스트.

### 매입내역
- 열: 번호, 사업자 구분, 품목, 매입처, 매입가, 총 판매가, 수익, 입금여부, 메모. 주·월 조회에서는 출고일 열을 더한다(행 기준은 출고일 × 품목).
- 품목은 판매내역이 생기면 자동 추가하고 이미 추가된 품목은 유지한다.
- 매입처는 그 품목에 등록된 매입처 중에서 드롭다운으로 고른다.
- 총 판매가 = 같은 출고일·같은 품목의 판매내역 판매가 합계. 수익 = 총 판매가 − 매입가. 매입가가 비어 있으면 수익은 '-'이고 총 수익에서 제외하며 "매입가 미입력 N건"을 알린다.
- 사업자 구분, 매입가, 입금 여부, 메모는 판매내역과 같은 방식이다.

### 사업자 관리
- 사업자등록증 정보(상호, 대표자, 사업자등록번호, 개업일, 사업장 소재지, 업태, 종목, 메모)를 등록·수정·삭제한다.

### 상품 관리 — 매입처
- 매입처(이름, 연락처, 메모)를 등록·수정·삭제한다.
- 상품을 여러 개 선택해 매입처를 한 번에 추가(또는 제거)한다. 한 상품에 매입처가 여러 개일 수 있다.

### 그래프
- 총 매입가, 총 판매가, 총 수익의 추이.
- 주·월 조회: 기간 안의 일별 선 그래프(차트 라이브러리 recharts를 쓴다).
- 일 조회: 선택한 하루만 보여주되 추이가 아니라 세 값을 나란히 비교하는 막대 그래프.

## 설계
| 테이블 | 용도 |
|---|---|
| `seller_businesses` | 사업자(우리 쪽 사업자등록) |
| `suppliers` | 매입처 |
| `product_suppliers` | 상품 ↔ 매입처(여러 개) |
| `settlement_sales` | 주문 줄 id가 기본키. 사업자, 판매가, 입금, 메모. 주문 줄이 삭제되면 함께 삭제 |
| `settlement_purchases` | (출고일, 품목명)이 기본키. 사업자, 매입처, 매입가, 입금, 메모. 사용자가 처음 입력할 때 행이 생긴다 |

- **판매내역은 읽을 때 계산**한다: 출고 완료(`src/lib/overview.ts`의 `stageOf`가 `done`)인 카드의 주문 줄. 입력값만 저장한다.
- **매입내역도 행 목록은 판매내역에서 계산한다**: 어떤 출고일에 어떤 품목이 판매내역에 올라오면 그 (출고일, 품목) 행이 자동으로 생긴다. 사용자가 입력한 값(`settlement_purchases`)은 판매내역이 나중에 바뀌어도 사라지지 않고, 입력한 행은 지금 판매내역에 없어도 계속 보여 준다("이미 추가된 품목은 유지"). 총 판매가와 수익은 저장하지 않고 화면에서 계산한다.
- 월 조회는 카드가 수백~천 개라 id를 나눠서 조회한다.
- 품목 기준은 상품명이다(매입처가 상품 단위라서).

## 권한
- 정산(`settlement`)과 사업자 관리(`sellers`)는 master만 기본으로 본다. 필요한 사용자는 "사용자 및 권한"에서 켠다(금액·수익이 민감하므로 자동 부여 마이그레이션을 두지 않는다).
- 매입처 등록·수정은 `products:edit`, 삭제는 `products:delete`를 쓴다.

## 단계(단계마다 따로 PR)
1. 마스터: 사업자 관리 + 상품 관리의 매입처
2. 판매내역(필터, 출고 완료 조회, 입력, 일괄 적용)
3. 매입내역(자동 추가, 매입처 선택, 총 판매가·수익) — 구현 완료(마이그레이션 0044)
4. 그래프(recharts 추가) — 구현 완료. 정산의 "그래프" 탭(`?t=chart`), 마이그레이션 없음(0044의 입력값을 읽는다)
