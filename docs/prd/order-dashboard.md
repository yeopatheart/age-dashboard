# 주문 수집 자동화 + 포장(박스) 추천 대시보드

## 목표 (성공 지표 1개 포함)

어머니가 매일 새벽 형의 카카오톡 주문 메시지를 화이트보드 2개에 50~60분 걸려 수기로 옮기고, 경험만으로 업체별 포장 박스 수량을 판단하는 과정을 자동화한다. 이 판단 로직이 어머니 머릿속에만 있어 어머니가 자리를 비울 수 없는 상태를 해소하는 것이 목적이다.

**성공 지표**: 어머니가 자리를 비워도 다른 사람이 이 대시보드만 보고 정상적으로 주문 수집·포장을 완료할 수 있는가.

## 안 만들 것 (Non-goals)

- **세분화된 역할별 권한(RBAC)**: admin/sales/worker/viewer 같은 세분화 대신, 개인별 로그인 + 접근 기록(감사 추적)만 둔다. 이유: 과거 직원이 유사 업종으로 창업한 사례가 있어 "누가 언제 봤는지" 추적은 필요하지만, 현장 작업자는 업무상 오늘 주문 전체를 봐야 하므로 화면별 접근 제한은 실익이 적고 구현 비용만 늘린다.
- **재고관리 화면**: 이 프로젝트 범위(주문 수집·포장 추천)와 무관.
- **실시간 동시편집 충돌 처리**: 카카오 메시지를 대시보드에 입력하는 주체가 사실상 형(또는 이를 대신하는 한 사람)뿐이라 동시 편집 시나리오가 실질적으로 없음. "새로고침하면 최신 상태" 수준으로 충분.
- **age-seafood와의 자동 대조 연동**: 주문 수량과 실제 송장 수량을 자동으로 맞춰보는 기능은 지금 만들지 않는다. 당장은 사람이 두 화면을 보며 눈으로 대조. 나중에 필요해지면 Supabase REST API를 통한 가벼운 배치 연동으로 확장 가능([[2026-09-29-order-dashboard-architecture]] 참고).

## 사용자 시나리오

현장에 있는 대부분의 사람이 이 대시보드를 본다.

1. **생선 손질 작업자**: 오늘 어떤 종류의 생선을 몇 마리씩 손질해야 할지 대시보드에서 판단한다.
2. **포장 작업자**: 오늘 어떤 업체에 어떤 종류의 생선을 얼마나 포장해야 할지 판단한다. 경매/시장에서 상품이 들어오면 중량·사이즈를 측정하고, 어느 업체 주문에 배정됐는지 기록해야 한다.
3. **대표**: 최종적으로 정리된 주문 대시보드를 기반으로 공급자·고객사에 정산을 진행한다.

## 요구사항

### 1. 카카오톡 메시지 기반 주문 입력
- 단일 텍스트 입력창에 형의 카카오톡 메시지를 복사-붙여넣기 한다.
- 시스템은 `docs/kakao-message-format-guide.md`에 정의된 포맷으로 각 줄을 파싱한다.
- 파싱된 각 줄의 업체명을 오늘 이미 등록된 주문과 자동으로 대조하여, 줄마다 "신규 주문으로 보임" 또는 "기존 업체 OO 주문에 업데이트로 보임"을 제안한다.
- 신규+업데이트가 한 메시지에 섞여 있어도 한 번에 붙여넣고, 확인 화면에서 사람이 줄 단위로 검토·수정 후 확정한다(age-seafood의 "AI 제안 → 사람 확인" 패턴 재사용).
- 주문번호는 카카오 메시지에 의존하지 않고 시스템이 내부적으로 생성한다: **업체번호-상품순서** 코드(예: "12-2" = 12번 업체의 2번째 상품 줄).
  - 업체 번호는 대시보드의 업체 카드 헤더에 1회만 표시.
  - 상품 순서 번호는 각 주문 줄마다 작은 배지로 표시.
  - 번호는 append-only로 부여하며, 항목이 삭제돼도 번호를 재사용하지 않는다.

### 2. 실측 중량/사이즈 기록 (하드웨어 연동)
- 작업장에 대형 TV 2대를 벽에 설치하여 주문 대시보드를 상시 표시한다.
- 경매/시장에서 상품이 들어오면, 재사용 가능한 화이트보드형 아크릴 카드에 "업체번호-상품순서 코드 + 실측 중량/사이즈"만 적는다.
- 카드는 TV 화면에 직접 붙이지 않고, 작업대 옆 별도 트레이/보드에 모아둔다.
- 트레이에 쌓인 카드를 주기적으로 일괄 촬영하고, age-seafood와 동일한 Claude Vision 기반 OCR로 코드+실측값을 읽어 시스템에 반영한다.
- 반영되는 즉시 해당 주문 줄이 화면에서 "완료" 색상으로 바뀌어, 카드를 TV에 붙이지 않고도 전체 작업자가 진행 상황을 한눈에 볼 수 있다.
- 파싱/인식이 애매한 카드는 "확인 필요" 표시를 남기고 사람이 검수한다.

### 3. 박스 포장 추천
- 형이 정리해온 기존 엑셀/장부 데이터(최소 최근 몇 개월치, 업체 기준 하루 50개 내외)와 예전 화이트보드 사진을 학습 데이터로 활용한다.
- 어머니 인터뷰를 통해 뽑아낸 명시적 판단 규칙을 보완 자료로 병행 반영한다(데이터에 없는 예외 케이스 커버).
- 구체적인 알고리즘(케이스 기반 유사도 조회 vs. 설명 가능한 회귀/결정 트리 등)은 실제 엑셀 데이터의 구조를 확인한 뒤 설계한다.
- **섀도우 모드로 검증**: 1차 버전을 ASAP으로 구축해 어머니의 기존 화이트보드/형의 엑셀 기록과 병행 운영하고, 시스템 추천값과 실제 기록값을 비교해 정확도를 측정한다. 정확도가 검증되는 대로 실제 운영으로 전환한다.

### 4. 인증
- 개인별 로그인 (Supabase Auth 재사용, age-seafood와 동일 패턴이되 별도 프로젝트).
- 로그인/접근 기록을 남겨 추적 가능하게 한다.

## 엣지 케이스와 실패 시 동작

| 상황 | 동작 |
|---|---|
| 카카오 메시지가 정해진 포맷과 안 맞아 파싱 실패 | 최대한 추측해서 반영하고, 불확실한 항목은 "확인 필요" 배지로 표시 → 사람이 확인 화면에서 수정 |
| 한 메시지에 신규 주문 + 기존 주문 수정이 섞여 있음 | 줄 단위로 AI가 신규/업데이트를 제안하고, 사람이 확인 화면에서 각 줄을 개별적으로 확정 |
| 아크릴 카드의 코드/중량 손글씨 인식 실패 | "확인 필요" 표시 → 사람이 검수 화면에서 직접 입력 |
| 같은 화면을 여러 명이 동시에 봄 | 입력 주체가 사실상 1인이라 동시 편집 충돌 없음. 단순 새로고침으로 최신 상태 반영 |
| 업체/상품 수가 늘어남 | 사업 특성상 변동폭이 크지 않다고 확인됨(하루 50개 내외에서 안정적) — 별도 확장성 설계 불필요 |

## 완료 기준 (체크리스트)

- [ ] 카카오 메시지 붙여넣기 → 줄 단위 파싱 → 신규/업데이트 AI 제안 → 사람 확인 → 확정까지 동작
- [ ] 업체번호-상품순서 코드가 대시보드에 표시됨
- [ ] 아크릴 카드 일괄 촬영 → OCR → 코드/실측값 반영 → 해당 줄 완료 색상 전환까지 동작
- [ ] 박스 포장 추천 로직이 최소 1개 버전으로 동작(정확도는 섀도우 모드에서 검증)
- [ ] 개인별 로그인 및 접근 기록 동작
- [ ] 섀도우 모드로 최소 1주 이상 병행 운영하여 정확도 데이터 확보

## 미결 질문

1. 실제 카카오톡 메시지 예시(특히 수정/취소가 어떻게 표현되는지) — 사용자가 추후 제공 예정.
2. 형이 정리한 기존 엑셀/장부 파일 — 사용자가 형으로부터 받아 추후 제공 예정. 박스 추천 학습 + 섀도우 모드 비교 기준으로 사용.
3. 예전 화이트보드 사진 — 보조 학습 자료로 추후 제공 예정.
4. 형과 협의할 메시지 포맷: 현재 제안은 "신규는 기존 포맷 그대로, 수정/취소는 원래 번호를 재사용"이나, 이 전제(형이 이전 번호를 기억하거나 대화를 스크롤해 조회할 수 있는지)가 실제로 성립하는지 확인 필요. **다만 최종적으로는 신규/업데이트 구분을 메시지 텍스트가 아니라 시스템의 업체명 자동 대조 + 사람 확인으로 처리하기로 했으므로, 이 포맷 협의의 우선순위는 낮아졌다.**
5. 어머니 인터뷰 일정 및 질문지 — 엑셀 데이터 구조 파악 후 설계 예정.
6. 아크릴 카드 일괄 촬영 주기(몇 분/몇 회마다 찍을지)는 실제 운영하며 조정.
