# 라벨 바코드(Code128) → QR 코드 (2026-11-08)

## 결정
- 박스 라벨에 찍는 코드를 Code128 1D 바코드에서 **QR 코드**로 바꾼다(사용자 결정). Code128 코드는 남기지 않는다(`jsbarcode` 제거).
- 내용은 지금과 같은 **숫자 12자리**(URL 아님). 폰 기본 카메라로 찍어도 번호만 보이고, 수동 입력·블루투스 스캐너 경로는 그대로다. DB·번호 규칙 변경 없음(마이그레이션 없음).

## 이유
- 접히는 선·구겨짐·결로·젖음에 QR이 강하다(오류 정정 H = 약 30% 복원). 1D 바코드는 막대 하나만 끊겨도 읽히지 않는다.
- 12자리 숫자는 QR 버전 1(21×21칸)에 오류 정정 H로도 들어가서, 측면 높이 2cm 띠에도 13mm 정사각형으로 들어간다(가로로 긴 1D 바코드보다 배치가 쉽다).
- 방향·각도에 덜 민감해서 쌓인 박스를 비스듬히 찍을 때 유리하다.

## 구현
- `qrcode`(MIT)로 칸 배열만 만들고(`src/lib/labels/qr.ts`), 그리는 일은 `label-view.tsx`가 한다. 칸 크기를 **프린터 도트(203dpi)의 정수배**로 내림해서 칸마다 도트 수가 들쭉날쭉해지는 것을 막는다.
- 스캔(`/scan`)은 ZXing 형식을 `QR_CODE`로, 조준선을 **정사각형**으로 바꿨다. 잘라 읽는 영역은 화면에 그려진 조준선 상자의 실제 위치를 읽어서 쓴다(CSS와 JS에 같은 비율을 두 번 적지 않는다).
- 시험 출력은 "QR 시험 출력": 같은 QR을 칸당 3·4·5·6·8·10도트로 한 장에 찍는다. 폰으로 읽히는 가장 작은 크기를 찾는 용도.
- 새 기본 배치: 상단 면은 터미널명(34pt)·고객명을 크게, QR을 오른쪽 위 21mm로 두고(사방 4mm 비움) 아래에 합포장·별도주문·번호·상호·연락처. 측면은 QR 13.1mm + 터미널·고객명·번호·날짜. 이미 저장된 디자인은 그대로이므로 라벨 설정에서 "기본 배치로"를 누르고 저장해야 새 배치가 적용된다.
- 저장된 디자인 JSON의 항목 type 값 `barcode`는 그대로 둔다(화면에는 "QR 코드"). 디자인 보관함(`label_designs`) 마이그레이션 때 `qr`로 바꿀지 함께 정한다.

## 확인하지 못한 것 (실물 시험 필요)
- 측면 QR(13.1mm, 칸 0.625mm = 5도트)의 실제 인식률. 부족하면 측면 높이를 25mm로 늘린다.
- 젖은·결로 라벨, 접히는 부분이 일어난 라벨에서의 인식률.
- 블루투스 스캐너는 2D 이미저 모델이어야 QR을 읽는다(Honeywell Voyager XP 1472g·Zebra DS2278은 2D). 레이저식 1D 스캐너는 QR을 못 읽는다.

## 다음 단계 (PR 2)
- 라벨 디자인 보관함(`label_designs`, 0050): 여러 디자인 저장·선택(출력은 "사용 중" 디자인, 시험 출력은 편집 중인 디자인), 프리셋 A(감아 붙이기)·B(윗면 전용).
- **접히는 선을 항목(요소)으로**: 추가·삭제·이동할 수 있게 한다. 접는선 요소가 없으면 윗면 전용 라벨이 된다. 접히는 선 위치(`top_height_mm`)와 측면 폭이 요소의 속성으로 옮겨가므로 새 테이블에서 한 번에 바꾼다. 옛 `label_templates`는 이전 뒤 나중에 따로 삭제.
