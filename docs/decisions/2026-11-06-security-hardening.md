# 2026-11-06 보안·성능 점검과 강화

현장 테스트(11/14) 전에 코드·DB·보안을 읽기 전용 감사(보안 / DB·성능 / 코드 품질)로 점검하고 결과를 반영했다.

## 결정
1. **RLS 범위: 민감 테이블만 메뉴 권한으로 묶는다(마이그레이션 0045).**
   대상은 정산 판매·매입, 사업자, 매입처, 상품-매입처, 카톡 원문, 시스템 설정, 접근 기록.
   버린 선택지: 전 테이블 묶기(메뉴↔테이블 매핑이 복잡하고 현장 직전 회귀 위험), 쓰기를 서버 전용으로 이전(56곳 재작성).
   남는 한계: 주문·박스·라벨 테이블과 `businesses`의 사업자번호·대표자명은 로그인 사용자 전체가 DB에서 읽을 수 있다.
2. **박스 추천 학습은 전체 이력을 유지하고 날짜 인덱스만 추가한다(0046).** 학습 결과가 달라질 수 있는 구간 제한은 현장 테스트 뒤 실측 시간을 보고 판단한다.
3. **CSP는 nonce 없이 정적 헤더로 둔다.** nonce 방식은 정적 페이지(/login)와 인라인 style 속성 때문에 지금 구조에서 화면이 깨진다. 스크립트 인라인은 허용하되 frame-ancestors·base-uri·form-action·connect-src·object-src를 막는다. 이후 nonce 전환은 별도 과제.
4. 현장 직전에는 큰 리팩토링(dashboard-client 분할, 서버 액션 공용 래퍼, commitOrderLines 트랜잭션화, 정산 월 조회 쿼리 수 줄이기, 디렉토리 캐싱)을 하지 않는다.

공개 가입 허용 여부, 프로젝트 region, JWT 만료 시간, Anthropic 지출 한도, 옛 GitHub 토큰 폐기 여부.
