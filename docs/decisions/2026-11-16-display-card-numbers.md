# 화면 업체 번호를 목록 순서대로 1번부터 (2026-11-16)

## 문제
11/16 주문 목록이 17번부터 시작했다. 형이 처음 입력한 16건을 목록에서 지우고 전체를 다시 입력했는데, 발급 번호(`daily_businesses.business_number`)는 하루 카운터가 올라가기만 하고 카드를 지워도 되돌아가지 않기 때문이다. 이 번호는 "오늘 출고할 고객사가 몇 곳인지" 세는 용도라 1번부터 빠짐없이 이어져야 한다.

## 결정 (사용자 확정)
- **화면에 보이는 번호는 발급 번호가 아니라 주문 목록 순서의 번호다**(`src/lib/card-number.ts`). 라벨·QR·DB의 발급 번호는 그대로다(이미 출력한 라벨이 있어 바꿀 수 없다).
- 번호는 **목록 순서(sort_order)대로** 센다: 끌어서 순서를 바꾸면 번호도 따라 바뀐다(주문 목록은 화면에서 바로 반영, 서버 화면은 같은 순서 값 → 발급 번호순).
- **상품이 모두 취소된 카드도 목록에 보이는 한 센다**(드문 경우라 따로 빼지 않는다).
- 1·2차는 목록에서 별개 줄이라 각각 센다. 별도 주문(택배·직배송 등)은 일반 주문과 따로 세고 **"별1, 별2…"**로 보여 준다(사용자 결정: 발급 번호 501~을 화면에 보이지 않는다). 별도 주문 팝업, 현황, 휴대폰의 별도 목록에 적용.
- 적용 화면: 주문 목록(PC 표·휴대폰), 현황. 박스 할당·상차 스캔은 업체 번호를 보여 주지 않아 바뀌는 것이 없다.
- 11/09 결정("화면 번호 = 라벨 번호", `2026-11-09-*`)을 이번에 바꾼다. 그때는 화면 순서와 라벨 번호가 따로 노는 것이 문제였고, 이제는 모든 화면이 같은 규칙(목록 순서)을 쓴다.

## 하지 않은 것
- 발급 번호 자체를 다시 매기거나 지운 번호를 재사용하지 않는다(이미 출력한 라벨의 QR 번호와 겹칠 수 있다).

## 확인
- 테스트 DB에서 발급 번호가 41·42·43인 카드가 주문 목록 PC·휴대폰·현황에서 12·13·14로 보였고 목록은 1~14로 이어졌다. 별도 주문 팝업은 발급 번호(501·502) 그대로.

- 별도 주문: 팝업·현황에서 발급 번호 501·502가 별1·별2로 보인다(테스트 DB).
