# 스마트 칠판(TV) 최적화 (2026-11-14 현장 시험 직후)

현장의 스마트 칠판(현대아이티 CX65NWPI)에서 대시보드를 보니 모니터와 다르게 보이고, 터치가 정교하지 않아 오작동이 있었다. 사용자가 6가지를 지적했고 아래와 같이 정했다.

## 결정
1. **상단 바는 무조건 한 줄.** `flex-nowrap`으로 고정하고, 터미널별 박스 수 칩은 남는 폭에 맞춰 글자·여백을 4단계(12/11/10/9px)로 줄인다(`TOOLBAR_CHIP_STEPS`). 그래도 넘치면 칩 줄 안에서만 가로로 민다.
2. **버튼 합치기.** 모니터 설정(전체보기·1·2)은 버튼 하나(현재 모드 표시)에서 메뉴로 고르고, `+`와 엑셀 다운로드도 버튼 하나의 메뉴로 합쳤다(보기 전용이면 다운로드만).
3. **"변경 N건" 칩 제거.** 최근 변경 목록은 알림 벨 패널 안으로 옮기고, 확인하지 않은 변경 수는 벨의 숫자 배지로 보인다. 탭 제목의 `(변경 N)`, "놓친 변경" 버튼, 소리 재생은 그대로다. "소리가 꺼져 있습니다 — 눌러서 켜기" 버튼도 한 줄을 지키려고 "소리 켜기"로 줄였다.
4. **칠판은 보기 전용.** 스마트 칠판은 마우스처럼 정교하지 않아 카드를 만질 때마다 포장 체크가 바뀌거나 수정 버튼이 눌렸다. 사용자는 "칠판 모드는 읽기 전용"으로 정했다. **다만 `board-mode`(실시간 알림)에 묶지 않고 기기별 별도 스위치(`board-view-only`, 알림 벨 패널 안 "칠판(보기 전용)")로 두었다.** 이유: 2026-11-07 현장 확인에서 형이 입력하는 PC에서도 실시간 알림을 켜고 쓰는 것으로 정해져 있어서, 알림을 켠 기기를 모두 보기 전용으로 만들면 그 PC에서 입력이 막힌다. 알림과 묶는 쪽이 원하면 `dashboard-client.tsx`의 `boardViewOnly` 한 줄을 바꾸면 된다. 보기 전용이면 카드 탭(포장 체크), 수정·미출고·취소·삭제, 순서 드래그, 주문 추가가 막힌다. 포장 체크는 휴대폰 화면이나 보기 전용을 끈 PC에서 한다.
5. **품목별 수량.** 패널 폭을 256px → 208px로 줄였다. 칩에 전체 수량과 함께 "추가분(+N)"을 보인다. **추가분 = 그날 첫 입력 이후 추가된 품목(`order_items.change_status = 'new'`)의 수량**(미출고·취소 제외, 전체에 포함). 한계: 이미 있던 품목의 수량을 늘린 것은 이전 수량을 저장하지 않아 추가분이 아니다. 추가된 품목을 나중에 수정하면 상태가 `modified`가 되어 추가분에서 빠질 수 있다. 선택하지 않은 안: 2차 주문(`round = 2`) 카드의 수량.
6. **옵션 글자.** 칩 안의 괄호 표기(`(키로5-6미, 기포기)`)에 상품명과 별도 크기(`--po`)를 두었다. 옵션이 상품명보다 2px 작게 시작하고, 칩이 넘치면 **옵션을 먼저 7px까지** 줄인 뒤에야 상품명·수량을 줄인다.
7. **사이드바 완전 접기.** 접으면 폭 0(`visibility: hidden`)이 되고 화면 왼쪽 끝의 작은 펼치기 탭(22×40px)만 남는다. 아이콘 줄(레일) 모드의 코드와 CSS, `--sidebar-width-collapsed`는 삭제했다. 휴대폰은 영향이 없다.
8. **펜 입력 진단 페이지** `/dashboard/pen-test` 추가(알림 벨 패널에서 이동). 칠판의 브라우저가 펜·손가락·손바닥·지우개·젖은 손을 어떤 입력(`pointerType`, 접촉 크기, 압력)으로 전달하는지 기록하고 결과를 복사해 전달할 수 있다. 서버에는 아무것도 저장하지 않는다.

## 펜 기능 (구현은 진단 결과 후, 2026-11-14)
사용자의 이상: 칠판에서 상품에 동그라미를 치면 자동으로 포장 완료 처리. (중량 인식은 **하지 않기로 했다** — 손글씨 정확도가 95%에 못 미치면 잘못 적힌 값을 다시 고치는 일이 늘어난다. 중량 관련으로 추가한 것은 없다. 대시보드의 `measured_weight_kg`는 박스 제출 때 쓰는 기존 기능이라 그대로다.)
- **칠판 업체 앱의 필기를 읽기: 어려움.** 같은 제조사 판서 앱은 웹 화면 위에 겹쳐 쓰는 오버레이이고(ZDNet 2023 체험기, 이 모델에 그대로 맞는지는 미확인), 웹페이지가 획을 읽는 API/SDK는 찾지 못했다. 남는 방법은 캡처 이미지 인식뿐이라 획 좌표가 없어 효용이 낮다.
- **우리 페이지 자체 펜 기능: 조건부 가능.** 동그라미는 획 좌표와 상품 칸 위치로 계산할 수 있어 보인다(이미지 인식 불필요). 가장 큰 미지수는 칠판 브라우저가 전달하는 `pointerType`과 손바닥·젖은 손 접촉 처리다 → `/dashboard/pen-test` 결과로 판단한다.
- **정해진 설계**
  - 도구함: **플로팅 버튼**(지름 56px 이상) + 펼치는 세로 도구함. 드래그로 옮기고 위치는 기기에 기억. 칠판(보기 전용) 기기 + 수정 권한 + 오늘 날짜에서만 보임. 도구를 고른 동안만 그림이 그려지고 접으면 터치가 통과한다. 이유: 65인치 벽걸이 칠판의 맨 위 툴바는 손이 닿기 어렵고 한 줄로 줄인 툴바에는 도구를 넣을 자리가 없다.
  - 도구: 펜(굵기 3단계, 색 5가지), 지우개(크기 3단계, 고른 뒤 버튼을 1초 꾹 누르면 전체 지우기), 되돌리기(최근 30단계, 전체 지우기도 되돌릴 수 있음).
  - 인식: 상품 칸을 충분히 감싸는 닫힌 원일 때만 그 상품을 포장 완료로 올린다. 이미 포장 완료면 해제하지 않는다. 두 상품에 걸친 원은 무시한다. 화면에는 표시 없이 뒤에서 처리하고 상품 칸이 포장 완료 색으로 바뀌는 것이 성공 표시다. 크기 기준은 칠판에서 시험하며 정한다.
  - 잉크 유지: 포장 완료로 인식된 원은 **해당 상품 칸에 붙이고**(칸이 움직여도 따라감), 그 외 낙서는 화면 좌표로 둔다. 날짜·모니터별로 이 기기에 저장해 새로고침해도 남긴다. 이유: 모니터 1·2에서는 상품 수가 늘면 모든 칸 폭이 바뀌어 화면 좌표의 원이 어긋난다.
  - **되돌리기 = 직전 펜 작업을 지우고 이전 단계로 돌아감.** 포장 완료로 올린 원을 되돌리면 그 상품의 포장 완료도 취소한다(사용자 확인). 지우개·전체 지우기는 화면의 그림만 지우고 포장 상태는 유지한다(제안, 펜 구현 때 다시 확인).
- 이 기능은 새 기능이라 구현 전에 요구사항을 한 번 더 정리한다.
- **대안(보류)**: 상차 스캔 시 포장 완료로 자동 처리. 포장 시간 리포트(`packed_at`)가 상차 시점으로 왜곡되고 현황의 "포장 완료" 단계와 "포장 체크 n/m줄" 경고의 의미가 사라지므로, 펜이 어려울 때만 설계를 따로 한다.

## 펜 입력 진단 결과 (2026-11-14, 칠판에서 측정)
- 칠판 브라우저: Linux Chrome 143, `maxTouchPoints` 2, **화면이 CSS 1280×720이고 `devicePixelRatio`가 3**(물리 4K). `pointer: fine=false`, `hover=false`.
- **펜·손가락·지우개가 모두 `pointerType = touch`, 접촉 1×1px, 압력 0.06 고정**으로 들어온다 → 펜과 손가락·지우개를 입력만으로는 구분할 수 없다. **손바닥만 큰 접촉(52×62px)** 으로 구분된다. 젖은 손은 기록하지 못했다(획 0).
- 설계에 미치는 영향
  - 펜 기능은 "도구를 고른 동안만 그린다"는 명시적 모드로 가는 것이 맞다(입력 종류로 자동 구분 불가).
  - 손바닥 거르기는 접촉 크기로 한다(기준값은 20~40px 사이에서 칠판에서 정한다). 한 획이 진행 중일 때 다른 접촉(손바닥, 두 번째 손가락)은 무시한다.
  - 지우개도 `touch`라 "지우개 도구"를 눌러 고르는 방식이어야 한다(펜 뒷면 지우개 같은 하드웨어 구분은 불가).
  - 동그라미 또는 대각선 → 포장 완료 설계는 그대로 가능하다(좌표 기반).
- **선이 깨져 보인 원인**: 캔버스 그림 해상도를 CSS 크기(1280 기준)로 잡아 배율 3으로 늘려 보이게 한 것. 공용 모듈 `src/lib/ink/canvas.ts`로 해상도를 `CSS 크기 × devicePixelRatio`로 잡고, 점이 듬성듬성 보고되는 적외선 터치도 매끄럽게 이어지게 곡선 보정을 넣었다. 실제 펜 기능도 이 모듈을 쓴다.
- **실제 칠판의 화면은 CSS 1280×720이다.** 이 크기에서 사이드바를 펼치면 표의 가로가 약 1000px뿐이라 모니터 1의 품목명이 8~11px로 작아지고, 사이드바를 접으면 10~11px(모니터 2는 12px)이다 → **칠판에서는 사이드바를 접어서 쓴다.**

## 상품 열 폭 상한 (2026-11-14, 같은 날 추가 지시)
- 모니터 1·2에서 상품 열이 적으면(예: 모니터 2에 상품 3열뿐) 열이 화면 폭만큼 늘어나 65인치 칠판에서 작업자가 고개를 많이 돌려야 했다. **상품 열 하나의 최대 폭을 200px로 제한**한다(`PRODUCT_COLUMN_MAX`).
- 기준: 가장 긴 한 줄 칩("활장어 2kg (키로6-8미, 기포기)")이 한 줄에 들어가는 폭이고, 1920px 화면에서 열이 9개일 때의 열 폭(사이드바를 펼치면 약 150px, 접으면 약 175px)보다 크다. 열이 그보다 많으면 지금처럼 화면 폭을 나눠 쓰므로 열이 적을 때만 작동한다. 값을 바꾸려면 상수 하나만 고치면 된다.
- 표 카드의 폭도 `고정 열 + 열 수 × 200px`를 넘지 않게 하고, 남는 폭은 오른쪽의 빈 자리가 된다. 모니터 2의 품목별 수량 패널은 표 바로 옆에 붙는다. 전체보기(스크롤 화면)는 바꾸지 않았다.
- 한계/대안: 열이 3개일 때 화면 오른쪽 절반 이상이 빈다. 빈 자리를 줄이려면 열 수가 적을 때 글자를 키우거나 표를 가운데에 두는 방법이 있는데, 칠판에서 보고 정한다.

## "박스" 칩을 고객명 칸에서 박스 칸으로 (2026-11-14, 같은 날 추가 지시)
- 이름 옆의 붉은 "박스" 칩의 뜻: 박스 할당에서 박스 구성을 정한 **뒤에 그 업체의 주문이 바뀌었다**는 경고(`packingChanged`)다. "박스 구성을 다시 확인하라"는 뜻이고 표시만 한다(동작은 막지 않는다).
- 문제: 고객명 열 폭은 가장 긴 고객명에 맞춰 정해지는데 칩 폭은 넣지 않아서, 이름이 짧은 날(11/14의 "스시히타", 열 폭 89px)에는 칩이 이름의 자리를 빼앗아 이름이 두 줄로 접히거나 잘렸다. **고객명은 절대 가려지면 안 된다**는 사용자 결정에 따라 고객명 칸에는 칩을 두지 않는다.
- 변경: 같은 정보를 **박스 칸**에 보인다 — 칸 배경이 붉게 바뀌고 박스 수 옆에 경고 아이콘(△)이 붙으며 마우스를 올리면 설명이 나온다. 합포장 표시와 함께 들어가도록 박스 열 폭을 80 → 88px로 넓혔다. 휴대폰·현황 화면의 "박스 재확인" 표시는 그대로다.

## 주문 목록 표 변경 (2026-11-14, 같은 날 추가 지시)
- **표의 상품 추가 `+` 칸을 없앴다.** PC에서 기존 주문에 직접 상품을 추가할 일이 없다는 사용자 판단이다. 열이 하나 줄어 상품 칸이 넓어진다(모니터 1·2). 상품 추가는 주문 입력 화면과 휴대폰 화면에서 한다. 업체 메모는 상품이 끝난 뒤 남는 첫 빈 칸부터 합쳐 보인다. 별도 주문 팝업의 상품 추가 버튼은 그대로 둔다.
- **상품 칸 여백을 줄여 글자를 키웠다.** 칸 바깥 여백 2 → 1px, 칸 안 좌우 여백 6 → 4px, 칩 안쪽 높이 `행 높이 − 7` → `− 5`, 기본 글자 14/11 → 15/12px(옵션은 상품명보다 2px 작게). 행 높이(30~40px 4단계)는 그대로여서 한 화면의 행 수는 변하지 않는다. 칩에 글자를 맞추는 기준은 `안쪽 높이 − 2` → `− 3`으로 1px 더 엄격하게 했다. 옵션을 7px까지 줄이는 설계 때문에 두 줄 칩(첫 줄 큰 수량, 둘째 줄 작은 옵션)의 글자가 칩 가운데보다 0.5~0.7px 위에 놓여 세로 중앙 점검이 1.1px 어긋났다. 줄 높이(1.0/1.05)를 바꿔도 해결되지 않아(오히려 1.4px), **옵션이 둘째 줄로 내려간 칩에만 0.6px 아래로 보정**(`--pshift`)했다.

## 확인한 것 / 못 한 것
- 브라우저(1920×1080, 1366×768, 1366×600)에서 모니터 1·2·전체보기, 행 높이 최소(30px) 단계까지 `text-clip-audit` 잘림·기준선·세로 중앙 위반 0건. 상단 바 높이 50px(한 줄) 유지(1920·1366). 1024px에서는 가장 작은 단계로도 칩이 넘쳐 칩 줄 안에서 가로로 민다.
- 보기 전용을 켠 상태에서 카드 탭에 서버 호출이 없고, 수정 버튼이 숨고, 추가 메뉴에 다운로드만 나오는 것을 확인했다(서버 호출 차단 장치를 걸고 시험).
