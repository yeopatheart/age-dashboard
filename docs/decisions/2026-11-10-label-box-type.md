# 라벨에 박스 종류 찍기 + 재출력 필요 안내 (2026-11-10)

## 배경
박스 종류 목록은 이미 `boxes` 테이블이고 `/boxes`(박스 관리)에서 추가·수정한다. 라벨 설정(`/labels`)은 라벨 디자인(크기·항목 배치)만 다루고, 라벨에는 박스 종류를 찍는 항목이 없었다. 요청은 "라벨 설정에서 박스 종류(최종 제출된 박스 종류)도 추가·설정"이었고, 사용자 확인으로 **라벨에 박스 종류 항목을 넣는 것**으로 정했다(박스 종류 목록 관리는 계속 `/boxes`).

## 결정
- **항목**: 라벨 디자이너에서 `항목`을 추가하고 `채울 값`을 **박스 종류**로 고른다. 위치·크기·글자 크기·굵기·정렬은 다른 항목과 같다. 기본 디자인(프리셋)에는 넣지 않는다. 이미 저장된 디자인은 바뀌지 않는다.
- **값**: 박스 할당에서 **제출한 박스 종류 이름**(`packing_boxes.box_name`, 제출 시점 스냅샷). 라벨 N번 = N번째 박스(`position + 1`). 제출 전이거나 이름이 없으면 빈 글자(라벨 출력은 원래 제출한 박스에만 허용된다).
- **재출력 필요 안내**(막지는 않는다): 사용 중인 디자인에 박스 종류 항목이 있고, 이미 출력한 라벨에 **찍힌** 박스 종류가 지금 제출된 박스 종류와 다르면, 박스 할당 화면의 라벨 영역에서 그 박스의 버튼이 "다시 출력"에서 "재출력 필요"(호박색)로 바뀌고 안내 문장이 나온다. 다시 출력하면 사라진다.
  - 판정을 정확히 하려고 출력할 때 라벨에 찍힌 값을 `box_labels.printed_box_type`(마이그레이션 0051)에 저장한다. `null` = 박스 종류를 찍지 않고 출력한 라벨(박스 종류 항목이 없는 디자인으로 출력했거나 이 기능 이전에 출력한 라벨).
  - 규칙: `(printed_box_type ?? '') !== 지금 박스 종류`이면 재출력 필요. 박스 종류 항목이 없는 디자인이면 경고하지 않는다. 그래서 박스 종류 항목을 디자인에 처음 넣은 날, 이미 붙인 옛 라벨(`null`)도 "재출력 필요"로 잡힌다.
  - 시간 비교(마지막 제출 시각 > 마지막 출력 시각)는 택하지 않았다. 상품만 고쳐 다시 제출해도 경고가 떠서 작업자가 무시하게 된다.
- 제출한 박스 종류는 서버가 아니라 `packing-log-client`가 `LabelPanel`에 `boxTypes`로 내려 준다. 박스 할당을 다시 제출하면 부모가 새 값을 내려 주므로 패널을 다시 읽지 않아도 경고가 최신이다.
- 순수 로직은 `src/lib/labels/reprint.ts`(판정·저장값), 테스트는 `src/lib/label-reprint.test.ts`.

## 마이그레이션 전 안전장치
- `loadCardLabels`는 `printed_box_type` 열이 없으면(`missingTable` → `label_printed_box_type`) 그 열 없이 다시 읽고 `printedBoxType = undefined`(알 수 없음)로 둔다. 이 경우 "재출력 필요"만 뜨지 않고 나머지는 그대로 동작한다. 없는 열 때문에 모든 라벨이 "미출력"으로 보이면 안 되기 때문이다.
- `prepareLabelPrint`도 열이 없으면 저장을 건너뛰고 출력은 그대로 진행한다.
- `MIGRATION_OF_TABLE`에 `label_printed_box_type: '0051_label_printed_box_type.sql'` 등록.

## 하지 않은 것
- 박스별 라벨용 약칭·색상, `/boxes` 화면 이동·중복, 추천 모델·백테스트 변경.
- 박스 종류를 바꿔 다시 제출한 직후 "이미 붙인 라벨" 자동 판별 외의 다른 경고(합포장 표시 변경 경고는 기존 그대로).

## 확인
- 단위 테스트(`label-reprint.test.ts` 7개), tsc, eslint 통과.
- 운영 화면(읽기만): 라벨 설정에서 `채울 값`에 박스 종류가 보이고 미리보기에 예시값이 찍힘. 박스 할당의 라벨 패널은 마이그레이션 0051이 없는 상태에서도 정상으로 열리고, 상태가 목록의 라벨 출력 표시(43곳 모두 미출력)와 일치함.
- 임시 하니스 페이지(DB 없음, 확인 후 삭제)로 재출력 필요 3가지 경우와 경고 없는 2가지 경우를 PC·모바일 폭에서 확인하고, `text-clip-audit.js` 잘림·세로 중앙 위반 0.
- **확인하지 못한 것**: 마이그레이션 적용 후 실제 출력(`prepareLabelPrint`)이 `printed_box_type`을 쓰는 동작과, 박스 종류를 바꿔 다시 제출했을 때 운영 화면에서 "재출력 필요"가 뜨는 흐름. 둘 다 운영 DB에 쓰기를 만들어야 해서 눌러 보지 않았다(테스트 Supabase에서 확인 가능).
