# 2026-11-10 보내기 기록 (보내기 화면 PR2 중 A)

## 결정
- "보내기" 화면(`/dispatch`)과 영수증 화면(`/receipts`)에서 기사 글·영수증을 **공유하거나 복사한 순간**을 `dispatch_log`(0052)에 남기고, 카드에 "보냄 ✓ 14:07" / "복사 ✓ 14:07"을 보인다. 새로고침해도 어디까지 보냈는지 남는다.
- 기록하는 경우: 공유 시트가 성공으로 끝남(`share`), 클립보드 복사 성공(`copy`, PC 포함). 기록하지 않는 경우: 공유 시트를 닫음, 복사 실패로 직접 복사 안내(prompt)로 넘어감, 영수증 이미지를 파일로 저장만 함 — 보냈는지 알 수 없다.
- 공유는 "보냄", 복사는 "복사"로 표시를 나눈다. 복사는 카카오톡에 붙여넣기까지 확인된 것이 아니다. 상차 스캔 이후 이 화면은 master만 쓰므로 "복사했다 = 보냈다"를 근사로 받아들이되, 표시는 구분한다(사용자 결정).
- 기사 글은 기록할 때 글의 해시를 같이 저장한다. 보낸 뒤 글이 달라지면(상차가 더 됨 등) "보냄 14:07 이후 변경됨"으로 바뀐다. 영수증은 발행 뒤 바뀌지 않아 해시를 두지 않는다.
- 같은 항목을 여러 번 보낼 수 있어 행을 계속 쌓고(unique 없음, 수정·삭제 정책 없음) 화면은 항목마다 가장 최근 기록만 쓴다.
- 새 권한 키를 만들지 않는다. 기사=`scan:view`, 영수증=`receipts:view`가 기록도 허용한다(서버 액션과 RLS 모두). `sent_by`는 DB가 `auth.uid()`로 채운다.

## 구현
- `src/lib/dispatch-log.ts`(순수: 해시·최근 기록 고르기·상태·표시 글, 테스트 `dispatch-log.test.ts`), `dispatch-log-server.ts`(조회), `dispatch/actions.ts`의 `recordSent`, `dispatch/use-sent-log.ts`(화면 상태).
- `useShareText`의 `copy`/`share`가 결과를 돌려준다(`/scan`의 동작은 그대로).
- 마이그레이션 0052 전에는 `rowsOrMissing`으로 읽어 화면이 열리고, 위에 안내를 보여 주며 기록은 건너뛴다.
- 영수증 카드 키는 `영수증id:쪽번호`라서 `/receipts`와 `/dispatch`가 같은 기록을 본다.

## 확인하지 못한 것
- 실제 DB에서의 0052 적용·보냄 → 새로고침 → 표시 유지 흐름(테스트 Supabase 접속 정보가 이 세션에 없어 운영 DB를 건드리지 않으려고 개발 서버를 띄우지 않았다).
- 모바일 공유 시트의 성공/취소 구분(실제 휴대폰에서만 확인 가능).
