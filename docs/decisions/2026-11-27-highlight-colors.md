# 2026-11-27 강조 상품 색: 글자색 다시 고름 + 해제해도 색 유지

## 문제
"강조할 상품"을 여러 개 고르면 색이 비슷해 헷갈렸다(예: 빨강·분홍). 색은 목록의 몇 번째인지로 정해서, 앞의 상품을 해제하면 남은 상품의 색도 전부 바뀌었다.
색 차이(ΔE2000)는 2번째 파랑↔3번째 보라 18, 파랑↔청록 18, 빨강↔분홍 21, 빨강↔갈색 25로, 3개째부터 비슷했다.

## 결정 (사용자 확정 2026-11-27)
1. **A안: 상품명의 글자색만 다시 고른다.** 상품명에 색 바탕을 칠하는 B안은 색 구분은 더 좋지만(4색 최소 44) **칩과 헷갈릴 것 같아** 채택하지 않았다.
2. **해제해도 남은 색 유지**: `daily_product_highlights.position`을 "색 자리"로 쓴다(`nextHighlightPosition`). 새로 고르면 비어 있는 색 중 앞의 것을 받고, 6개를 넘으면 앞 색부터 다시 쓴다. DB 스키마 변경은 없다.

## 색 (고르는 순서)
빨강 `#dc2626` → 파랑 `#1d4ed8` → 올리브 `#6d7411` → 갈색 `#502c0b` → 자홍 `#d6009d` → 물빛 청색 `#23768b`.
고른 개수별 가장 비슷한 두 색의 ΔE2000: 2개 46, 3개 46, 4개 30, 5개 30, 6개 21 (예전: 46, 18, 18, 18, 18).
- 색 후보는 칩 바탕(최초·추가·수정)에서 대비 4.5 이상인 진한 색 전체에서 찾았다. 빨강 계열은 첫 색 하나만 두었다.
- **상태 글자색과 겹치지 않게**: "추가됨" 칸의 일반 상품명은 초록(emerald-700), "수정됨" 칸은 황토(amber-700)다. 처음 검토안의 청록(`#0f766e`)은 추가 글자색과 차이 9, 올리브(`#4d7c0f`)는 18이라 버렸다. 그래서 초록·청록 계열 강조색을 쓰지 않는다.

## 구현
- `src/lib/highlight-colors.ts`(+테스트: 서로의 차이, 칩 바탕 대비 4.5 이상, 2번째 이후 색과 상태 글자색의 차이, 색 유지 규칙).
- 칩 바탕·테두리·글자 크기는 바꾸지 않는다. 취소·포장 완료 칸은 지금처럼 강조하지 않는다.

## 감수한 점
- 진한 글자색은 서로 확실히 다른 것이 3개 정도가 한계다. 4개부터는 이전보다 낫지만(30), 앞 3색만큼 확연하지 않다. 갈색은 작은 글자에서 검정 기본 글자와 비슷해 보일 수 있고, 6번째 청색은 파랑과 가장 비슷하다(21).
- 첫 색 빨강은 "수정됨" 칸의 황토 글자와 차이가 16이다(예전부터 같은 빨강). 강조 이름은 더 굵게 쓴다.
- 이미 강조가 켜져 있던 날짜는 저장된 position에 따라 색이 달라진다.
- 4개 이상에서 구분이 부족하면 다음 후보는 색이 아닌 보조 표시(밑줄 모양 등)다.
