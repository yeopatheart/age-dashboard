# 2026-11-08 라벨 디자인 보관함 (QR 전환 PR 2)

## 결정
- 라벨 디자인을 **여러 개 저장**해 두고, 라벨 설정에서 고른 하나를 **"사용 중"** 으로 지정한다. 박스 라벨 출력(박스 할당 화면)은 사용 중 디자인으로 나가고, "테스트 출력"·"QR 시험 출력"은 지금 편집 중인 디자인으로 나간다. 사용 중 지정은 **라벨 설정에서만** 바꾼다(출력 화면에서 고르지 않는다).
- 이전의 "시안 시트(A4에 크기별로 비교 출력)"는 지웠다. 사용자가 원한 것은 비교용 시트가 아니라 **저장해 두고 그 디자인대로 출력**하는 것이다(`label-mockup-*`, `lib/labels/mockup.ts` 삭제).
- **접는선은 항목의 한 종류**(`type: 'fold'`)다. 라벨 위에서 끌어 위아래로 옮기고, 속성에서 위치(`y`)·옆면 폭(`w`, 가운데 기준)을 바꾼다. 접는선이 **없으면 윗면 전용 라벨**이다(접는선 제한 없음). 한 디자인에 하나만, 인쇄되지 않는다.
- 새 디자인은 **프리셋**(감아 붙이기 / 윗면 전용) 또는 **저장된 디자인 복제**로 시작한다. 프리셋은 코드(`LABEL_PRESETS`)에 둔다 — 저장된 디자인이 하나도 없어도 시작점이 있어야 하기 때문이다.

## 구현
- 테이블 `label_designs`(0050): `id, name(고유, 대소문자 무시), width_mm, height_mm, elements jsonb`. 사용 중 id는 `app_settings` 키 `labelActiveDesign`. 사용 중 지정이 없거나 지워진 디자인을 가리키면 가장 먼저 만든 디자인을 쓴다.
- 0050이 기존 `label_templates` 한 행을 "기존 디자인"으로 옮기고(`top_height_mm`→접는선 `y`, `side_width_mm`→접는선 `w`) 사용 중으로 지정한다. `label_templates` 테이블은 **지우지 않았다**(앱은 더 읽지 않음). 확인 뒤 따로 삭제한다.
- `LabelTemplate`에서 `topHeightMm`·`sideWidthMm`을 없애고 `foldOf(template)`로 읽는다. `elementProblem`은 접는선이 있을 때만 접는선 주변·옆면 폭 밖을 검사한다. `normalizeTemplate`가 접는선을 라벨 크기 안으로 맞춘다(저장·읽기·크기 변경 때).
- 삭제 규칙: 사용 중인 디자인과 마지막 하나는 지울 수 없다. 처음 만드는 디자인은 자동으로 사용 중이 된다. 사용 중 지정은 저장된 내용 기준이라, 저장하지 않은 변경이 있으면 "이 디자인을 사용"이 잠긴다.
- `rowsOrMissing` + `MIGRATION_OF_TABLE`(`label_designs` → 0050). 마이그레이션 전에는 라벨 설정이 안내를 보여 주고, 박스 라벨 출력은 코드의 기본 배치(감아 붙이기)로 계속 나간다.
- 복제는 서버에 저장된 내용을 복사한다(저장하지 않은 편집 중 내용이 아님).

## 확인하지 못한 것
- 실제 DB에서의 0050 적용·저장·삭제 흐름(운영 DB에 연결된 개발 서버라 저장 동작은 누르지 않았다). 화면의 디자인 전환·접는선 추가·끌기·경고 표시는 임시 점검 화면(DB 없이)으로 확인했다.
- 윗면 전용 프리셋(B)의 QR(23.6mm)·글자 크기의 실제 출력 상태는 프린터 도착 후 시험.
