# 2026-11-19 필기 이력 보관을 "7일"에서 "최근 2영업일"로 (설정 가능)

## 결정 (사용자 확정 2026-11-19: 기본 2영업일, 이 방식으로 진행)
- 보관 기준을 달력 7일에서 **최근 N영업일**로 바꾼다. 설정 `boardInkHistoryKeepDays`(1~30 정수, 기본 **2**), 시스템 설정의 "칠판 필기 백업" 카드에서 바꾼다. 저장하면 다음 점검부터 적용된다.
- **영업일 = 오늘(한국 시간) 이전·당일 날짜 중 이력이 있는 날짜(`order_date`)**. 일요일·공휴일은 이력이 없으므로 세지 않는다: 월요일에는 월요일과 토요일만 남는다. 달력이나 휴무일 설정이 따로 필요 없다.
- 최신 날짜부터 N개를 남기고 더 오래된 날짜의 이력을 모두 지운다.
  - 오늘 이력이 아직 없는 새벽에는 직전 N일이 그대로 있고, 오늘 첫 이력이 생긴 뒤 다음 점검(최대 5분 뒤)에 가장 오래된 날이 지워진다.
  - **오늘보다 뒤 날짜**(내일 미리 입력한 주문의 필기)는 세지도 지우지도 않는다.
  - 같은 날짜의 화면(모니터 1·2·별도 주문)은 하루로 센다.
  - 날짜 기준이 `captured_at`이 아니라 `order_date`라서, **과거 날짜의 필기를 고쳐도 최근 영업일 이력이 밀려나지 않는다.** 대신 그 과거 날짜의 급감 이력은 남기자마자 정리된다(과거 날짜 필기는 이력 대상이 아니다).
- 삭제는 정기 점검(5분마다, 시간대와 상관없이 맨 앞)과 급감 스냅샷을 남길 때 **같은 함수**(`board_ink_history_prune`)가 한다. 이전에는 두 곳에 `7 days`가 따로 박혀 있었다.
- 삭제가 실패해도 점검의 스냅샷 기록과 칠판 저장은 계속된다(예외 격리).

## 바뀐 것
- `supabase/migrations/0071_board_ink_history_keep_days.sql`: `board_ink_history_keep_days()`(설정 읽기, 잘못되면 2), `board_ink_history_prune()`(삭제), `board_ink_snapshot()`(급감 트리거)·`board_ink_snapshot_tick()`(정기 점검)을 prune 호출로 교체. 0068·0070이 먼저 적용돼 있어야 한다. 함수만 바꾸므로 앱 배포 전후 어느 쪽에 적용해도 안전하다.
- `src/lib/app-settings.ts`(+테스트), `settings-client.tsx`: 입력 항목·검증(1~30 정수가 아니면 저장 버튼을 막음)·안내 문구. 이력 화면 안내 문구의 "7일"을 바꿨다.
- **적용하면 곧바로(다음 점검, 최대 5분 안에) 최근 2영업일보다 오래된 이력이 삭제된다.** 되살릴 수 없다. 설정을 3으로 바꿔 저장하면 그다음 점검부터 3일을 남기지만 이미 지운 날은 돌아오지 않는다.
- 되돌리기: 0068의 `board_ink_snapshot`, 0070의 `board_ink_snapshot_tick` 정의를 다시 실행하면 7일 보관으로 돌아간다(삭제된 이력은 복구 불가).

|---|---|---|

## 위험·한계
- **금요일 실수를 월요일에 발견하면 이미 없다**(2영업일은 월요일에 월·토만 남는다). 필요하면 설정에서 3으로 올린다(월요일에 금요일까지 남음). 주말을 낀 늦은 발견이 걱정되면 3 이상을 권한다.
- 정산 확인·분쟁처럼 일주일 전 필기를 다시 봐야 할 일에는 쓸 수 없다. 이력의 목적은 "필기가 잘못됐을 때 직전 상태 되찾기"다.
- 이력이 쌓인 날짜 수가 N보다 적으면 아무것도 지우지 않는다(운영 시작 직후 등).
- 운영 DB에서 한국 시간 판단(`at time zone 'Asia/Seoul'`)은 직접 확인하지 않았다(0070과 같은 방식).

## 적용 순서
1. 0071을 **테스트 DB에 먼저** 적용하고(프로젝트 이름 확인) 확인한 뒤 운영 SQL Editor에 적용한다. 0068·0070이 먼저 있어야 한다.
2. 확인(테스트 DB):
   ```sql
   select board_ink_history_keep_days();                 -- 기본 2
   select order_date, count(*) from board_ink_history group by 1 order by 1 desc;
   select board_ink_history_prune();                      -- 지운 행 수(권한 때문에 SQL Editor의 postgres 권한으로)
   ```
3. 앱을 배포하면 설정 화면에 "이력을 보관할 영업일 수" 항목이 나온다(SQL만 적용해도 설정이 없으면 2로 동작).
