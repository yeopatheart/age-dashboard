# 빈 박스·출력 전 라벨·번호 밀림 규칙 (2026-11-09)

E2E 점검(B-1·B-3·B-4·B-5·C-1)에서 나온 문제를 한 묶음으로 푼다. 마이그레이션 없음. 순수 규칙은 `src/lib/packing/box-rules.ts`(단위 테스트 `packing-box-rules.test.ts`).

## 결정
- **상품이 없는 박스는 제출할 수 없다.** 서버(`submitPacking`)가 막고 화면(`canSubmit`, 안내 문구)도 같은 규칙을 쓴다. 빈 박스에 라벨이 나가면 상차 때 영원히 찍히지 않는 박스가 되어 "n/m박스" 상차가 끝나지 않고(`/scan`, `/overview`, 퀵 기사 공유글), 박스 수 집계(목록·리포트)도 부풀기 때문이다. 집계 곳곳을 각각 고치지 않고 입구에서 막는다.
- **이미 제출된 빈 박스는 자동 정리하지 않는다.** 그 업체를 열면 "n번 박스가 비어 있습니다"로 안내하고, 박스를 지운 뒤 다시 제출하면 정리된다.
- **제출한 뒤 취소·삭제된 상품은 박스 구성(작성본)에서 뺀다**(B-1). 남겨 두면 재제출이 "주문에 없는 상품이 포함돼 있습니다"로 막혔다. 이 때문에 비게 된 박스는 위 규칙이 안내한다.
- **라벨은 제출한 박스에 대해서만 출력한다**(B-4). 서버(`prepareLabelPrint`)가 제출 기록의 박스 수를 확인하고, 화면의 라벨 영역은 작성 중인 박스가 아니라 제출한 박스 수를 기준으로 한다. 제출 전에는 출력 버튼이 없다.
- **출력한 라벨이 있는데 마지막이 아닌 제출 박스를 지우면 확인을 받는다**(B-3, 차단하지 않고 경고만). 뒤 박스 번호가 앞당겨져 붙여 둔 스티커와 어긋나기 때문이다.

## 하지 않은 것
- 박스 삭제 시 번호 재부여 방지(번호 고정)나 `submitPacking` 원자화(B-11).
- 빈 박스를 서버에서 자동 제거하는 것(어떤 박스를 지울지 사람이 정해야 한다).
- 운영 DB의 기존 빈 박스 정리(SQL로 건수 확인 뒤 판단).

## 확인하지 못한 것
- 서버 쪽 두 검사(빈 박스 거부, 제출 전·범위 밖 출력 거부)는 화면이 먼저 막아서 브라우저로는 직접 부딪히지 못했다(규칙 함수는 단위 테스트로 확인).
