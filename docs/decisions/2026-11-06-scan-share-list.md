# 2026-11-06 상차 완료 목록 복사·공유 (`/scan`)

> **2026-11-10 갱신**: 상차 스캔 화면의 터미널별 **공유·복사 버튼은 제거**했다. 같은 글은 보내기 화면의 퀵기사 탭([dispatch-screen](2026-11-10-dispatch-screen.md))에서 보낸다. 스캔 화면은 터미널별 상차 현황(몇 박스/전체)과 업체 목록만 보여 주며, 더 많은 업체가 한 화면에 보이도록 터미널 타일·업체 줄·카메라가 꺼진 시작 영역을 낮췄다. 글 형식 설정(`scanShare`)은 보내기 화면이 계속 쓴다.

아버지가 라벨 바코드를 스캔하면(`box_labels.loaded_at`) 예전의 "라벨 사진 → 카톡 → 형 → 퀵 기사님" 단계가 필요 없다. 형이 퀵 기사님께 보낼 글을 복사·공유하도록 `/scan` 상차 현황에 버튼을 둔다. DB 변경·새 server action 없음(이미 `requireMenu('scan')`을 통과한 화면의 데이터로 클라이언트에서 만든다).

**수정(현장 피드백)**: 처음에는 전체 터미널을 한 통으로 만들었으나, 형은 터미널 단위로 퀵 기사님께 따로 보낸다(대구 기사님께는 대구 고객만). 그래서 **전체 버튼을 없애고 터미널 타일(`sc-term`)마다 복사·공유 버튼**을 둔다.

```
11/06(금) 대구 상차 완료
타다시 5박스
김가네 2/3박스
합계 7박스
⚠ 미상차: 김가네 1박스
```

| # | 결정 | 이유·대안 |
|---|---|---|
| 1 | 터미널 타일마다 공유(`navigator.share`, 지원하는 브라우저에서만 보임)·복사(항상) 아이콘 버튼. 공유 실패(취소 제외)는 복사로 대체, 복사 실패는 `window.prompt`. "복사됨"은 누른 타일에만 표시. | 형은 주로 휴대폰이라 공유 시트로 카톡을 바로 연다. 데스크톱은 복사. 좁은 타일에서는 `--chip-h` 아이콘 버튼. |
| 2 | 글은 터미널 하나씩, 고객별 박스 수 + `합계 N박스`. 일부만 스캔된 고객은 `2/3박스`로 목록에 넣고 `⚠ 미상차` 줄에 그 터미널의 남은 수를 적는다. 상차 0건 고객은 경고 줄에만. 그 터미널에 상차 완료가 0건이면 그 타일의 버튼은 비활성. | 사용자 확정. |
| 3 | 1·2차(`round`)는 합산한다. | 퀵 기사님은 어느 고객 박스를 몇 개 싣는지만 알면 된다. 차수를 나누면 줄이 길어진다. |
| 4 | 합포장은 묶음 하나를 1박스로 센다(묶음 안 라벨이 모두 상차된 때만 상차 완료). | 기사님이 실제로 싣는 덩이 수와 맞아야 한다. 대신 화면의 `loaded/total`(라벨 수)과 숫자가 다를 수 있다. |
| 5 | 택배(`is_parcel`)는 별도 처리 없음. | 택배는 라벨을 출력하지 않아 `box_labels`가 없고 `/scan` 카드에서 이미 빠진다. |
| 6 | 과거 `?date=`는 그대로 동작하며 글 머리에 해당 날짜가 찍힌다. | 날짜는 `orderDate` 기준이다. |

로직은 `src/lib/scan-share-text.ts`(순수 함수, 터미널 이름을 받아 그 터미널 글만 만든다). 퀵 기사 구분 필드는 DB에 없어 이번 범위가 아니다(터미널·고객 단위까지).
