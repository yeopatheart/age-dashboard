# 2026-11-06 상차 완료 목록 복사·공유 (`/scan`)

아버지가 라벨 바코드를 스캔하면(`box_labels.loaded_at`) 예전의 "라벨 사진 → 카톡 → 형 → 퀵 기사님" 단계가 필요 없다. 형이 퀵 기사님께 보낼 글을 한 번에 복사·공유하도록 `/scan` 상차 현황에 버튼을 둔다. DB 변경·새 server action 없음(이미 `requireMenu('scan')`을 통과한 화면의 데이터로 클라이언트에서 만든다).

```
11/06(금) 상차 완료
[대구] 타다시 3박스 / 김가네 2/3박스 (5)
[해운대] 박씨네 1박스 (1)
⚠ 미상차: 김가네 1박스 / 이씨네 2박스
```

| # | 결정 | 이유·대안 |
|---|---|---|
| 1 | 공유 버튼(`navigator.share`, 지원하는 브라우저에서만 보임) + 복사 버튼(항상). 공유 실패(취소 제외)는 복사로 대체. | 형은 주로 휴대폰이라 공유 시트로 카톡을 바로 연다. 데스크톱은 복사. |
| 2 | 터미널별로 묶고 그 안에서 고객별 박스 수. 일부만 스캔된 고객은 `2/3박스`로 목록에 넣고 경고 줄에도 남은 수를 적는다. 상차 0건 고객은 경고 줄에만. 상차 완료가 0건이면 버튼 비활성. | 사용자 확정. |
| 3 | 1·2차(`round`)는 합산한다. | 퀵 기사님은 어느 고객 박스를 몇 개 싣는지만 알면 된다. 차수를 나누면 줄이 길어진다. |
| 4 | 합포장은 묶음 하나를 1박스로 센다(묶음 안 라벨이 모두 상차된 때만 상차 완료). | 기사님이 실제로 싣는 덩이 수와 맞아야 한다. 대신 화면의 `loaded/total`(라벨 수)과 숫자가 다를 수 있다. |
| 5 | 택배(`is_parcel`)는 별도 처리 없음. | 택배는 라벨을 출력하지 않아 `box_labels`가 없고 `/scan` 카드에서 이미 빠진다. |
| 6 | 과거 `?date=`는 그대로 동작하며 글 머리에 해당 날짜가 찍힌다. | 날짜는 `orderDate` 기준이다. |

로직은 `src/lib/scan-share-text.ts`(순수 함수). 퀵 기사 구분 필드는 DB에 없어 이번 범위가 아니다(터미널·고객 단위까지).
