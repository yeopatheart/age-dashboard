# 상차 완료 카카오톡 메시지 형식 설정 (2026-11-09)

## 배경
상차 스캔에서 터미널별로 퀵 기사님께 카카오톡으로 보내는 글(`buildLoadedListText`)이 고정 문구였다. 문구·표기를 바꾸려면 코드를 고쳐야 했고, 날짜·터미널명·고객사명·박스 수·합계 같은 값을 원하는 자리에 넣을 수 없었다.

## 결정(사용자 확인)
- **시스템 설정에 "상차 완료 카카오톡 메시지" 카드를 추가**한다(`settings/scan-share-card.tsx`). **구조형 4칸** — 첫 줄 / 업체별 줄(업체마다 반복) / 합계 줄 / 미상차 줄(미상차가 있을 때만) — 에 문구와 `{변수}`를 쓰고, 입력칸 아래 변수 칩을 눌러 커서 위치에 넣는다. 날짜 형식(`11/06(금)`·`11월 6일(금)`·`2026-11-06`)과 미상차 줄 켜기/끄기를 고른다. 줄 순서는 고정이다. 자유 텍스트 + 반복 구간 표기 방식은 일반 사용자가 실수하기 쉬워 택하지 않았다.
- **모든 터미널이 같은 형식**을 쓰고 `{터미널명}`으로 터미널마다 다르게 나온다(터미널별 예외는 필요해질 때 추가).
- 줄마다 쓸 수 있는 변수: 첫 줄·합계 줄 `{날짜} {터미널명} {업체수} {합계}`, 업체별 줄 `{고객사명} {박스수} {상차박스} {전체박스}`(`{박스수}`는 모두 상차면 숫자, 일부면 `3/5`), 미상차 줄 `{미상차목록} {날짜} {터미널명}`.
- **저장**: `app_settings`의 `scanShare` 키(jsonb 객체, 마이그레이션 없음). 읽기는 로그인한 모든 사용자(RLS select), 쓰기는 `settings:edit`. 서버(`saveSettings`)가 모르는 변수·그 줄에서 못 쓰는 변수·짝이 안 맞는 중괄호·줄당 120자 초과를 거부하고, 화면은 같은 규칙으로 이유를 보여 주며 저장 버튼을 막는다. `/scan`은 서버에서 설정을 읽어 `ScanClient`에 넘긴다.
- **기본값 = 이전 고정 문구와 같다**(단위 테스트로 보장). 설정을 건드리지 않으면 글이 달라지지 않는다. 비워 둔 줄은 글에서 빠지고, 마지막은 항상 `cleanShareText`로 앞뒤 공백·빈 줄을 정리한다.
- 순수 로직은 `src/lib/scan-share-template.ts`(템플릿 값·검증·치환)와 `scan-share-text.ts`(렌더). `scan-share-text.ts`의 import를 상대 경로+`.ts`로 바꿔 처음으로 단위 테스트(`scan-share-text.test.ts`)가 생겼다.

## 끝의 빈 줄(미해결: 앱 밖일 가능성이 높다)
앱이 만드는 글에는 끝 줄바꿈·공백·빈 줄이 없음을 확인했다(운영 화면에서 복사 버튼이 클립보드에 쓰는 글을 가로채 `\n` 종료·`\n\n` 여부를 검사했고, 단위 테스트도 같은 것을 검사한다). 공유(화살표) 버튼은 `navigator.share({ text })`에 같은 글을 넘긴다. 사용자는 **폰의 공유 버튼**으로 보낼 때 카카오톡에서 끝에 빈 줄이 생긴다고 했으므로, 공유 창 → 카카오톡 사이(OS/카카오톡)에서 붙는 것으로 보인다.
- 확인 방법: 같은 글을 **복사 버튼 → 카카오톡에 붙여넣기**로 보내 빈 줄이 생기는지 본다.
  - 복사 경로에는 빈 줄이 없으면: 공유 경로의 문제로 확정 → 공유 버튼의 동작을 바꾼다(후속 작업).
  - 복사 경로에도 있으면: 글에 보이지 않는 문자가 있는지 더 파고든다.
- 설정 화면 미리보기에 "글 끝에 줄바꿈 없음 ✓"와 안내 문구를 넣어 두었다.

## 확인하지 못한 것
- 설정을 **저장**하는 동작(`app_settings` upsert)은 운영 DB에 쓰기를 만들어 눌러 보지 않았다(화면의 입력·미리보기·검증, 기본 문구 일치, 복사되는 글은 운영 화면에서 읽기만 확인).
- 공유(화살표)로 카카오톡에 실제로 보냈을 때의 모양(빈 줄 여부)은 이 환경에서 확인할 수 없다.
