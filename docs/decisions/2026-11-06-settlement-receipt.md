# 2026-11-06 정산 영수증(기존 Auto-Receipt 이관)

기존 영수증 전용 서비스(Auto-Receipt V2)를 정산 메뉴로 옮긴다. 정산 판매내역 입력이 채워진 고객사별로 영수증 이미지를 만들고, 다운로드하거나 카카오톡으로 전달한다.

## 결정
1. **영수증 한 장 = 고객사 × 사업자 × 출고일.** 한 고객에게 사업자가 줄마다 다르면 장이 자동으로 나뉘어 공급자 정보가 섞이지 않는다.
2. **카카오톡은 사람이 보낸다.** 앱은 이미지를 만들고 다운로드·모바일 공유 시트(Web Share)·PC 이미지 복사를 제공한다. 카카오 비즈니스 API 자동 발송은 채널·템플릿 심사·건당 비용·고객 전화번호가 필요해 범위 밖이다(공식 문서는 확인하지 않았다).
3. **발행 이력은 스냅샷으로 DB에 저장한다**(`settlement_receipts`, 마이그레이션 0047). 이미지는 저장하지 않고 이력에서 열 때 같은 컴포넌트로 다시 그린다. 직인은 용량 때문에 스냅샷에 넣지 않고 현재 사업자의 직인을 쓴다.
4. **직인은 사업자 마스터(`seller_businesses.seal_image`)에 작은 PNG data URL로 저장한다.** 공개 주소가 없고 정산·사업자 권한이 있는 사용자만 DB에서 읽는다(기존 앱은 `public/seals`로 누구나 받을 수 있었다). 이미지 변환 때 외부 주소 요청이 없어 iOS Safari에서 도장이 깨지는 문제도 피한다.
5. **단가는 판매내역에서 직접 입력한다**(`settlement_sales.unit_price`). 단가를 입력하면 판매가를 단가 × 수량(원 단위 반올림)으로 채우되 판매가는 그 뒤에도 고칠 수 있다. 영수증의 금액 열과 합계는 항상 판매가다.

## 기존 앱에서 이관하지 않는 것(버그 또는 취약점)
- 15품목 초과 시 첫 장만 출력되던 문제 → 모든 장을 출력한다.
- 상단 "공급대가총액"과 하단 "합계"가 다른 값에서 오던 문제 → 같은 합계를 쓴다.
- 직인 크기·위치를 사업자 이름 문자열로 분기하던 하드코딩 → 직인 이미지 자체를 알맞은 크기로 저장한다.
- 로그인 없음 + RLS 해제 + 소스에 하드코딩된 Supabase 키 → 새 앱은 로그인과 DB 권한 정책(`has_perm`)을 쓴다. 이관 후 기존 사이트를 내리고 그쪽 키를 교체한다.

## 디자인
기존 영수증을 그대로 재현한다: 폭 420px 흑백, Noto Serif KR, 제목 "영 수 증", 공급자 표(등록번호·상호·성명(인)·소재지·업태·종목), 작성년월일·공급대가총액·비고, 품목표(월일·품목·수량·단가·공급대가) 15행(빈 행은 대각선), 합계, "위 금액을 청구(영수)함".

## 단계
1. 0047 마이그레이션, 타입, 묶기·분할 순수 로직과 테스트(`src/lib/settlement/receipt.ts`)
2. 사업자 관리에서 직인 등록
3. 단가 입력, 영수증 화면, 이미지 변환, 발행·다운로드·공유·복사
4. 정산 "영수증" 이력 섹션
