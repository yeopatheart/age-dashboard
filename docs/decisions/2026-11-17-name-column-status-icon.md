# 고객명 열 폭 버그 수정: 완료·취소 표시 몫을 항상 예약하고 아이콘으로 줄인다 + 터미널 칩 축소 (2026-11-17)

## 맥락
- 현장 증상: 완료·취소가 된 줄의 긴 고객명이 칸 밖으로 약 19px 잘린다(모니터 1·2의 dense 줄).
- 원인(코드로 확인): `dashboard-client.tsx`의 고객명 열 폭은 "가장 긴 이름 + 1·2차 배지 28px + 20px"(칸 좌우 여백 16 + 경계선 1 + 여유 3)이다. 완료 배지·취소 배지는 "상태에 따라 붙었다 떨어지므로" 폭에서 일부러 뺐다. 그런데 칸은 `overflow-hidden whitespace-nowrap`라, 배지가 붙은 줄은 그 몫(dense 완료 배지 약 22px = 체크 8 + px-1 8 + 테두리 2 + mr-1 4)만큼 이름이 밀려 3px 여유로는 모자랐다(22 − 3 = 약 19px 잘림).
- 같은 칸의 메모 점(ml-1 + w-1.5 = 10px)도 폭에 안 들어 있었다. 메모가 있는 줄에서 같은 식으로 밀린다.
- 별도 주문 팝업의 고객명 칸은 이 열 폭(`nameColumn`)을 쓰지 않는다(`minmax(150px, 1.3fr)` 가변 칸, 글자 배지를 항상 씀). 그래서 이름 잘림은 모니터 1·2·전체 보기 표의 문제다.

## 결정 (사용자 확정)
1. 완료/취소 표시 몫을 줄의 상태와 무관하게 **항상 예약**한다. 같은 이름 목록이면 줄이 완료돼도 열 폭이 바뀌지 않는다.
2. dense(줄 높이 30px 미만 = 모니터 1·2의 15~18px 줄)의 표시는 테두리·배경 없는 **맨 아이콘**으로 바꿔 몫을 줄인다: 체크(emerald)·×(rose), 크기 `min(12, max(10, 업체명 글자 + 2))`px, 고정 폭 슬롯 **14px**(아이콘 최대 12px + 오른쪽 간격 2px). 이전 22px → 14px.
   - 아이콘은 고객명 칸(flex, items-center)의 첫 자식이라 이름 줄의 기준선과 무관하게 칸 가운데에 놓인다(인라인 `align-middle` 배지는 쓰지 않는다).
   - 슬롯은 완료/취소 줄에만 그려진다(빈 줄에 빈 자리를 그리지 않는다). 폭 예약은 열 단위라 이름이 밀리는 줄은 있어도 잘리는 줄은 없어야 한다.
3. dense가 아닌 화면(전체 보기, 줄 30px 이상)은 글자 배지(`완료`/`취소`) 모양을 그대로 두고, 폭 예약만 실제 배지 폭에 맞춘다: 완료 배지 = 테두리 2 + px-1 8 + 체크 10 + gap 2 + "완료" 20 + mr-1 4 = 46px(추정: 굵은 10px 한글 한 글자를 1em으로 본 값), 취소 배지는 34px라 큰 쪽을 따라 여유 2px을 더해 **48px**.
4. 메모 점 10px은 메모가 있는 줄만 폭에 넣는다(`nameSignature`에 메모 유무를 추가). 1·2차 배지 28px 예약은 그대로다. 상한 `NAME_COLUMN_MAX` 220과 하한 72는 그대로다.
5. **터미널 칩 축소**(dense만): 글자 `min(11, 줄−5)` → `min(9, 줄−5)`, 좌우 패딩 `px-2`(8px) → `px-1.5`(6px). 열 폭 측정도 같은 규칙으로 바꿨다: 글자는 표시와 같은 `terminalChipFontPx`로 재고, 여백은 칩 패딩 12 + 테두리 2 + 칸 여백 16 + 여유 4 = **34**(기존 38). dense가 아니면 11px·px-2·38 그대로. 최소 56은 유지한다: 표 머리 "터미널"(12px 굵게 약 36px + 칸 여백 16 + 경계선 1)이 들어가는 폭이고 표 머리는 이 변경 범위 밖이다. 최대 120도 그대로다.
   - 별도 주문 팝업의 터미널 칩도 같은 규칙(dense 판정이 같다)이라 함께 바뀐다. 팝업 터미널 열 76px는 그대로이고, 칩이 더 작아졌으므로 기존에 들어가던 이름은 계속 들어간다(칩 안 글자 가용 폭 42px → 46px).
   - 상단 툴바의 터미널별 박스 칩(`--tb-fs`)은 다른 변수라 건드리지 않았다.
6. 계산은 순수 함수로 분리했다(`src/lib/name-column.ts`, 테스트 `name-column.test.ts`). 글자 폭 측정(`canvas.measureText`)만 호출하는 쪽에 남기고 측정기를 인자로 받는다.

## 대표 값 (글자 폭은 측정기 값이라 실제는 글꼴에 따라 다르다)
- 이름 61px, 1·2차·메모 없음, dense: 61 + 14 + 20 = **95px**(이전 81px). 1·2차 배지가 붙으면 +28, 메모가 있으면 +10.
- 이름 61px, 전체 보기: 61 + 48 + 20 = **129px**(이전 81px).
- 터미널 이름 4글자(9px 굵게 한글 약 36px), dense: 36 + 34 = **70px**(이전 11px 44 + 38 = 82px). 2글자(약 18px): 52 → 최소 56(이전 60).

## 한계 · 확인하지 못한 것
- **열 폭이 바뀌면 줄 안 필기의 가로 위치가 움직인다.** 필기는 줄에 붙여 저장하지만 가로는 줄 폭에 대한 비율이라, 고객명 열이 넓어지고 상품 열이 그만큼 좁아지면(모니터 1·2는 열을 화면 폭에 맞춰 나눈다) 이미 써 둔 필기가 줄 안에서 옆으로 움직여 보일 수 있다. 영업이 끝난 뒤 배포하고, 배포 전 `board_ink` 백업을 권한다. 칠판에서 쓴 필기가 같은 칸에 있는지 점검이 필요하다.
- 고객명 열이 최대 약 +14px(dense)·+48px(전체 보기) 넓어지고 상품 열이 그만큼 좁아진다. 상품 열 글자 단계(`widthShrink`)는 열 폭에서 구하므로 상품이 많은 날 한 단계 작아질 수 있다(상품 칩 글자 규칙 자체는 바꾸지 않았다). 칠판에서 상품 칩 글자 크기가 달라졌는지 본다.
- `scripts/text-clip-audit.js`는 로그인된 화면이 필요해 돌리지 못했다. "잘림 없음"을 확인하지 않았다. 완료·취소·메모·1·2차 배지가 겹친 줄의 이름, 아이콘의 세로 가운데, 터미널 칩 글자가 칩에 들어가는지는 배포 후 `textClipAudit`·`textVerticalCenterAudit`로 확인해야 한다.
- 한글 한 글자를 1em으로 본 것(글자 배지 슬롯 48px, 칩 글자 폭)은 Noto Sans KR 기준 추정이다. 웹폰트가 늦게 뜨면 폰트 로드 후 다시 재도록 되어 있다(기존 동작).
- dense 슬롯이 이름과 14px 안에서만 간격을 둔다: 아이콘이 크기 12px일 때 이름과의 간격은 2px뿐이라 붙어 보일 수 있다(눈으로 확인하지 못함).
