# 박스 할당 / 라벨 출력 PC 화면 압축 (2026-11-09)

## 문제
PC에서 업체를 고르면 오른쪽 작업 영역이 길어서 스크롤이 많았다(운영 화면, 1366×768 실측): 박스 1개 업체 약 500px, 2개 약 550px, 3개 약 1000px. 위에서 아래로 제목+설명(68)·도구줄(58)·작업 헤더(70)·추천 줄·보드(361, `min-height: 22rem`)·제출 푸터·**라벨 영역**이 쌓였고, 라벨 영역이 박스마다 큰 카드(약 395px: 미리보기 265 + 출력 버튼 52)를 2열로 나열해 가장 길었다.

## 결정(사용자 확인: 미리보기 목업을 보고 방향 승인)
- **라벨 영역 = 미리보기 1개 + 박스별 한 줄 목록**(`label-panel.tsx`). 미리보기는 선택한 박스 하나만 그리고(목록의 행을 누르면 바뀐다), 박스는 "박스 N번 · 상태 · [출력/다시 출력]" 한 줄씩 나열한다. 박스가 많으면 목록만 안에서 스크롤한다(`max-height: 14rem`). 미리보기 배율은 1mm=3px → 2.1px(라벨 100mm가 약 210px). 실제 인쇄 경로(`prepareLabelPrint`, `LabelPrinter`)와 인쇄 크기는 그대로다.
- **PC(901px 이상)에서만 압축**(`packing-log-client.tsx`): 제목 줄과 날짜·필터 도구줄을 한 줄로 합치고(설명 문구는 한 줄로 단축), 작업 헤더·추천 줄·보드·푸터의 여백을 줄이고, 보드 `min-height`를 없애고, 제출 버튼을 약간 작게, 박스 카드는 3열이 들어가도록 최소 폭을 줄였다. 휴대폰(900px 이하)은 기존 레이아웃·터치 크기를 유지한다. 라벨 영역은 좁은 작업 영역에서 미리보기를 위로 쌓고 줄·버튼을 `--cta-h`(48px) 기준으로 키운다.

## 결과(운영 화면 읽기 전용 측정, 업체 선택만, 변경 전 → 후, 스크롤 길이)
| 화면 | 박스 1개 | 박스 2개 | 박스 3개 |
|---|---|---|---|
| 1366×768 | 499 → 105px | 547 → 53px | 1004 → 53px |
| 1440×900 | 5px 이하(사실상 없음) | 〃 | 〃 |
| 1920×1080 | 0 | 0 | 0 |

## 하지 않은 것 / 한계
- 박스 카드(상품 줄) 자체는 건드리지 않았다. 한 박스에 상품이 많으면(상품 5개 한 박스) 그만큼 높다.
- 박스 12개 같은 극단 경우는 운영 데이터에 없어 측정하지 못했다(목록만 안에서 스크롤되는 구조라 라벨 영역은 늘지 않는다).
- 박스별 라벨을 한눈에 비교하던 카드 나열은 사라졌다(선택한 박스 1개만 미리보기).
- 목록의 출력 버튼으로 실제 출력하는 흐름은 운영 DB에 쓰기를 만들어서 눌러 보지 않았다(호출 경로 `print`/`prepareLabelPrint`는 변경 없음).
