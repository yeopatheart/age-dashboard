# 업체 번호 통일 · 1·2차 표기 · 어제 라벨 차단 (2026-11-09)

E2E 점검(B-2·B-6·C-6·C-3)에서 나온 문제를 한 묶음으로 푼다. 마이그레이션 없음.

## 결정
- **화면의 업체 번호는 라벨·QR의 업체 번호(`daily_businesses.business_number`)와 같다**(사용자 결정 1-a). 주문 목록(PC 표·별도 주문 창)·모바일 주문 목록·개요(`/overview`)가 예전에는 화면 순서(index+1)를 번호로 썼다. 그래서 월미도는 목록 3번인데 라벨은 016이었고, 카드를 지우거나 순서를 바꾸면 번호가 달라졌다. 이제 순서를 바꿔도 번호는 그대로이므로 16, 3, 4처럼 비단조로 보이는 것이 의도한 결과다. `/scan`·`/packing-log`는 원래 `business_number`를 썼다.
  - 모바일 번호 원(`.dm-no`)은 `min-width: 22px`로 두어 1~2자리 크기는 그대로이고 세 자리면 늘어난다(100번 이상에서 잘리지 않음). PC 표의 번호 칸은 40px 열이라 세 자리까지 들어간다.
- **같은 날 1차·2차가 둘 다 있는 업체만 이름에 차수를 붙인다**(사용자 결정 1-a): 라벨(`loadCardLabelBase`), `/scan` 목록·결과 배너. 한 차수뿐인 업체는 그대로다(라벨 글자 절약). 함수는 `nameWithRound`(`src/lib/orders.ts`). 라벨 필드·저장된 디자인 스키마는 그대로라 기존 디자인이 깨지지 않는다. 이미 출력한 1차 라벨에는 접미사가 없고, QR은 번호 기반이라 스캔은 그대로 된다(다시 출력하면 바뀐다).
  - 퀵 기사 공유글(`scan-share-text`)은 이름으로 1·2차를 합산하므로 `ScanCard.business`는 바꾸지 않고 `roundLabel` 필드를 따로 둔다.
- **오늘이 아닌 날짜의 라벨은 상차하지 않는다**(차단, 사용자 확인: 자정을 넘겨 상차하는 날은 없다). 라벨 번호 앞 6자리(YYMMDD)가 주문일이다(`barcodeOrderDate`). `scanBarcode`가 서버에서 막고 `{ status: 'past' }`를 돌려주므로 화면에서 우회할 수 없다. 어제 스티커를 찍어도 `loaded_at`을 오늘로 덮어쓰는 일이 없다.

## 하지 않은 것
- 자정을 넘겨 상차하는 경우를 위한 확인 후 허용(그런 날이 없다고 해서 단순 차단으로 했다. 필요해지면 확인창 방식으로 바꿀 수 있다).
- `undoScan`의 날짜 가드(되돌리기는 이미 상차한 박스에만 가능해서 같은 문제가 없다).

## 확인하지 못한 것
- 차수가 붙어 길어진 이름의 실제 인쇄 크기(라벨 글자는 FitText가 줄인다고 코드 주석으로만 확인했다).
