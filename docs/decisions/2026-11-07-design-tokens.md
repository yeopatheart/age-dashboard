# 2026-11-07 디자인 기준(토큰) 정리

사용자 요청: "컴포넌트 간 여백, 표 글자 크기가 중구난방이다. 사용자 관점에서 E2E로 점검해 모든 요소를 통일감 있게."

## 점검 결과(PC 1440px, 18개 화면 측정)
- 페이지 제목 20px(대시보드)·22px(나머지), 카드 제목 15/16/16.8px(굵기도 600/700/800)
- 블록 사이 간격 14·16·20·22·24·28px, 화면 루트 안쪽 여백이 대시보드만 별도(이중 여백), 스캔 화면만 가운데 정렬
- 카드 모서리 8/10/12/14/16px, 안쪽 여백 9.6/12/13.6/14.4/16/17.6/20px, 그림자 있음/없음 혼재
- 표 머리 12px·본문 13/14px, 글자 크기 10·11·11.2·12·13·14·15·16·16.8·17.6·19.1·21.6·22·24·29.6px

## 기준
| 항목 | 값 |
|---|---|
| 글자 | xs 12(휴대폰 13×0.875=11.4) · sm 13 · md 14 · lg 16 · xl 20 · num 24(휴대폰 17.5). 휴대폰은 html 14px라 모두 한 단계 작게 보인다. |
| 간격 | 블록 16 / 카드 안쪽 16 / 카드 안 요소 12 (휴대폰 12 / 12 / 9.6) |
| 모양 | 카드 = 흰 배경 + 1px 테두리 + 12px 모서리 + shadow-sm, 카드 안 항목은 테두리만. 버튼·선택칸 알약, 글자 입력칸 10px |
| 제목 | 페이지 20/800, 카드·구역 16/800 |
| 표 | 머리 xs/700 높이 40, 본문 md 높이 48 |

## 적용
globals.css 토큰, admin.css(`.ak-page`·도구줄·표·구역 제목), 대시보드·박스 할당·상차 스캔·정산 그래프·리포트·주문 입력·설정·사용자·영수증·주문 목록(모바일)의 화면별 스타일의 글자 크기(rem)를 토큰으로 바꾸고, 루트 간격·카드 안쪽 여백·모서리를 토큰으로 맞췄다. 대시보드의 화면 안쪽 이중 여백과 스캔 화면의 가운데 정렬을 없앴다.

## 그대로 둔 것
- PC 주문 목록(표 화면 UI 유지 요청), 상차 스캔의 큰 결과 글자(야외·아버지 사용), 박스 라벨 미리보기·영수증 이미지(출력물), 필터 칩 모양(별도 정리 대상).

## 추가 점검: 컨트롤 글자 크기 (같은 날, 2차)
사용자 지적: "판매내역 표에서 사업자 구분·고객명만 같고 나머지는 다르다. 필터 글자도 메뉴마다 다르다."
- 원인: PC에서 선택칸(13px)만 입력칸·본문(14px)과 달랐고, 휴대폰은 입력·선택칸이 16px 고정(`--input-fs`)이라 표 글자(12.3px)·필터(11.4px)보다 커 보였다. 검색 입력(14px)·도구줄 요약 문구(14px)도 버튼(13px)과 달랐다.
- 기준: **자리마다 하나** — 도구줄 안(검색·선택·버튼·건수·합계 문구) = sm, 표 안(입력칸·선택칸·본문) = md, 표 머리 = xs. 휴대폰은 `--input-fs`를 자리별로 덮어(도구줄 sm, 표 md, 기본 md) 같은 크기가 된다.
- **결정(사용자 선택)**: 입력칸 글자를 통일하는 대신 iOS 자동 확대를 `maximum-scale=1`로 막는다(11/6에 일부러 풀었던 제한을 되돌림). 아이폰은 핀치 확대 그대로, 안드로이드 크롬은 핀치 확대가 막힌다. 이전(입력칸만 16px) 결정은 `docs/decisions/2026-10-29-mobile-ui.md`.
- 측정 확인: PC는 정산 표 한 행의 모든 칸 14px, 모든 화면 글자가 12/13/14/16/20/24 안(스캔·박스 번호 큰 글자는 24). 휴대폰은 11.4/12.3/14/17.5 안.
- 알게 된 것: 개발 서버의 `.next` 캐시가 옛 CSS를 계속 내보내 측정이 틀어질 수 있다. 스타일이 안 바뀌면 개발 서버를 멈추고 `.next`를 지운 뒤 다시 띄운다.
