# 대시보드(진행 현황) 메뉴 — 2026-10-29

## 배경
상차 스캔 상태(`box_labels.loaded_at`)가 스캔 화면과 라벨 패널에만 보이고, 기존 "대시보드"(주문 목록)의 "완료" 배지는 포장 체크만 뜻했다. "주문이 몇 곳이고, 얼마나 포장·상차됐고, 얼마나 남았는지"를 한 화면에서 볼 곳이 없었다.

## 결정
- 새 메뉴 **대시보드**(`/overview`, 권한 `overview:view`)를 맨 앞에 둔다. 기존 대시보드는 **주문 목록**(`/dashboard`, 키·경로는 그대로)으로 이름만 바꾼다. 읽기 전용이다.
- 현장 순서는 박스 할당 → 라벨 출력 → 포장 → 상차이고, **라벨 출력 전에는 포장을 시작하지 않는다**(사용자 확인). 그래서 고객 카드의 단계는 "처음으로 안 끝난 단계"로 정한다:
  박스 할당 중 → 라벨 출력 중 → 포장 중 → 포장 완료(상차 대기) → **상차 중**(박스 일부만 스캔) → 출고 완료. 계산은 `src/lib/overview.ts`.
- 단위가 섞이는 문제(라벨·상차는 박스 단위, 나머지는 고객사 단위): **단계는 고객사 단위로 세고, 박스 단위 진행은 고객 행 안에서 보여준다.**
  - 라벨 출력 중 = 박스 수만큼 라벨이 아직 안 나옴, 상차 중 = 상차 스캔이 1개 이상 있고 전부는 아님. 분모는 발급된 라벨 수가 아니라 박스 수다.
  - 박스 번호마다 점 하나(○ 라벨 미출력, 파랑 출력, 초록 상차)를 `src/components/box-dots.tsx`로 그린다. 현황 화면과 주문 목록 카드가 같은 모양을 쓴다.
  - 맨 위에는 곳 단위 단계 막대·단계별 곳 수(누르면 목록 필터)와 박스 합계 한 줄을 따로 둔다.
- **택배**는 택배사 송장을 붙이므로 박스 라벨을 출력·스캔하지 않는다(사용자 확인). 터미널 관리에 "택배" 토글(`terminals.is_parcel`, 마이그레이션 0038)을 두고 켜면 별도 주문도 함께 켠다. 택배 터미널은 박스를 화면에서 정하지 않고 1박스로 보며, 박스 할당·라벨 출력 단계를 건너뛰어 포장 중 → 출고 완료(포장이 끝나면)로 간다. 택배 외 별도 주문(직배송 등)은 기본 주문과 똑같이 박스 할당 → 라벨 → 상차를 거친다(박스 1개 기본값도 택배에만 적용).
- 박스 할당 뒤 주문이 바뀐 고객("박스 재확인")은 단계를 되돌리지 않고 경고 표시만 붙인다(주문 목록과 같은 기준 `findChangedAfterPacking`).
- 주문 목록(모바일) 카드에도 같은 단계 칩·박스 점·설명을 붙인다.
- 마이그레이션 `0037`: `dashboard:view` 권한이 있는 기존 사용자에게 `overview:view`를 부여한다.

## 열린 것
- PC 주문 목록(표)에는 단계 표시를 넣지 않았다(PC UI 유지 요청). 필요하면 별도로 정한다.
- 택배는 포장이 끝나면 "출고 완료"로 센다(택배사 인계는 이 시스템에서 관리하지 않는다). 인계 확인 단계가 필요하면 따로 정한다.
- 박스 할당 화면(`/packing-log`)의 라벨 패널은 택배 카드에서도 아직 보인다. 숨길지는 따로 정한다.
- 박스 점은 번호(seq) 기준으로 그린다. 박스를 줄여 남은 번호의 라벨은 점에도 단계 계산에도 넣지 않는다.
- 현황은 새로고침 버튼으로 갱신한다(자동 갱신·실시간 구독은 하지 않았다).
