# 2026-11-22 칠판 스티커 (상품 칸에 붙이는 특이사항 표시)

## 배경
어머니가 칠판에서 중량 말고도 특이사항("특대 1", "냉동실" 등)을 펜으로 상품 칸 위에 쓴다. 매번 쓰는 일이 번거롭다. 자주 쓰는 특이사항을 미리 만들어 두고 골라서 붙이게 한다. 목록에 없는 예외는 지금처럼 펜으로 쓴다.

## 확정한 결정 (사용자, 2026-11-22)
- **붙는 곳**: 상품 칸(order item). 업체별 반복 메모가 아니다(매일 반복되지 않고 업체별로도 반복이 아님).
- **붙이는 법**: 스티커를 고르고 상품 칸을 탭한다(드래그·위치 조정 없음). 수량을 쓰는 스티커는 칸 아래에 **숫자 말풍선**이 뜬다. **1~10은 누르는 즉시 붙고(확인 버튼 없음), 11 이상은 `11+`로 전체 키패드**를 쓴다. 수량이 없는 스티커(`냉동실`)는 탭하는 순간 붙는다. 붙인 뒤에도 같은 스티커가 선택돼 있어 다음 칸을 바로 탭할 수 있다. 이미 붙은 스티커를 탭하면 수량 바꾸기·삭제 말풍선이 뜬다. 스티커 모드의 칸 탭은 포장 완료를 토글하지 않는다(`readOnly`에 스티커 모드를 포함한다).
- **수량**: 정수만. **한 칸에 스티커는 최대 2개. 같은 스티커를 한 칸에 두 번 붙일 수 없다**(이미 있으면 수정 말풍선).
- **보이는 곳**: 칠판(모니터 1·2, 같은 마크업을 쓰는 PC 전체보기). 모바일·별도 주문 팝업·이력 화면은 이번에 제외.
- **상차가 끝나도 그대로 둔다**(흐리게 하거나 지우지 않는다). 포장 완료(회색) 칸에도 붙을 수 있어야 한다(`냉동실`은 포장 뒤에 붙인다).
- **목록 관리는 PC에서**(메뉴 "스티커 관리", `/stickers`). 어머니가 추가·수정·삭제하고 두 분도 같은 화면에서 한다.
- **칠판 도구 버튼은 4개를 따로 보이게 한다**: 펜·지우개·스티커·되돌리기. 한 묶음으로 끌어서 옮기고(기본 세로 한 줄), 버튼 크기는 지금(56px 이상)보다 조금 줄인다. 펜·지우개는 **길게 누르면 설정 카드**가 열린다. 지금 지우개를 1초 누르는 "전체 지우기"는 지우개 설정 카드 안의 버튼으로 옮긴다(되돌리기로 복구되므로 확인 창은 두지 않는다).

## 자리가 모자랄 때의 순서 (사용자 확정)
스티커의 위치는 저장하지 않고 그릴 때마다 계산한다. 이웃 칸 상태가 바뀌면(오른쪽 빈 칸에 상품이 들어오는 등) 다음 갱신에서 자동으로 다음 순서로 넘어간다.
1. **칸 안**: 글자를 바닥(7px)까지 줄여서 스티커를 글자 흐름 끝에 끼워 넣는다. 글자를 가리지 않는다.
2. **오른쪽 빈 칸**: 1이 안 되면, 오른쪽에 빈 칸이 있을 때(새 열을 만들지 않고) 오른쪽 칸에 왼쪽 정렬로 붙인다. 그 줄의 마지막 상품이면서 업체 메모가 없는 줄에서만 가능하다(메모가 남은 빈 칸을 모두 차지한다).
3. **아래, 안 되면 위의 빈 칸**: 2가 안 되면, 아래 줄의 같은 열 칸이 비어 있으면 그 칸에, 아니면 위 줄의 칸에, 자기 칸에 **2px 이내로 걸치게** 붙인다. 업체 메모가 있는 줄의 빈 칸, 모니터의 첫·마지막 줄 밖은 비어 있지 않은 것으로 본다.
4. **반투명 얹기**: 1~3이 모두 안 되면 칸 오른쪽에 우측 정렬로 반투명하게 얹는다(투명도는 칠판에서 정한다).

알려진 위험: (3)은 다른 업체 줄의 빈 칸에 놓이므로 그 업체 것으로 읽힐 수 있다(칠판에서 어머니와 확인). 걸침은 글자를 건드리지 않아야 하므로 글자 잘림 점검 세 가지로 확인한다. 이웃 줄이 바뀌면 스티커가 옮겨 가 보일 수 있다. 줄임 표기·줄임 이름 열은 두지 않는다.

## 설계
- 필기(`board_ink`)와 **별개 데이터**로 둔다. 필기 앵커 규칙을 건드리지 않는다. 스티커 도구는 펜과 같은 묶음에 놓이지만 펜이 켜지면 스티커 모드는 꺼진다(반대도 같다).
- 테이블 2개, 마이그레이션 2개로 나눈다(PR마다 SQL 적용을 한 번씩만 하도록).
  - 0074 `sticker_presets`(스티커 목록: 이름·색·수량 입력 여부·순서). 이름은 8자까지, 같은 이름 중복 불가, 색은 `color-palette`의 key.
  - 다음 마이그레이션 `order_item_stickers`(상품 칸에 붙은 스티커). 붙을 당시의 이름·색을 복사해 둔다(목록을 고쳐도 오늘 칠판은 그대로). 칸당 최대 2개, 같은 칸에 같은 이름은 불가(unique), 상품이 지워지면 함께 지워진다. realtime 대상에 추가한다.
- 권한: 새 메뉴 `stickers`(보기·등록수정순서·삭제). 목록 읽기는 로그인 사용자 전체(칠판이 읽는다), 쓰기는 DB에서도 `has_perm`으로 막는다. **어머니 계정에는 "사용자 및 권한"에서 이 메뉴를 한 번 켜 줘야 한다**(기본값이 없다).
- 칸마다 후보 위치(안쪽·오른쪽·아래·위·반투명)를 모두 그려 두고, 글자 맞춤이 끝난 뒤 첫 번째로 가능한 위치만 보이게 한다. 칸 안쪽에 넣었다 뺐다 하는 상태 변경이 없으므로 효과에서 `setState`를 반복하는 문제(CLAUDE.md 2026-11-16)를 피한다.

## PR 순서
1. 스티커 목록 관리(PC): 0074, 메뉴, 서버 동작. 칠판 변화 없음.
2. 칸에 표시: 두 번째 마이그레이션, 읽어 오기·realtime, 위 4단계 위치 규칙. 스티커가 없으면 화면이 그대로다. 글자 잘림 점검(`scripts/text-clip-audit.js` 세 가지: 잘림·기준선·세로 중앙)을 모니터 1·2·전체보기에서 돌린다. 열 수를 늘려 열 폭 변화에 따라오는지도 확인한다.
3. 칠판 도구 4버튼 묶음(3a): 동작은 그대로 두고 배치와 길게 누르기만 바꾼다. "칠판 확인 필요".
4. 스티커 붙이기(3b): 스티커 버튼·선택 띠·숫자 말풍선·수정·삭제. "칠판 확인 필요".

## PR 2 구현 메모와 측정 (2026-11-22)
- 마이그레이션 0075 `order_item_stickers`: 업체 카드 id(`daily_business_id`)를 같이 저장해 주문 줄과 **같은 단계에서 병렬로** 읽는다(주문 줄을 읽은 뒤 또 읽는 왕복이 없다). 칸당 2개는 트리거, 같은 이름은 unique. Realtime 발행 등록 SQL만 넣고 **구독은 PR 3b로 미뤘다**(스티커를 만드는 곳이 PR 3b이고, `use-live-refresh`는 칠판의 가장 민감한 경로라 PR 2에서 건드리지 않는다).
- 못 읽어도 주문 목록은 열린다: 스티커 조회 오류는 로그만 남기고 스티커 없이 보여 준다(0075 없이도 주문 목록 정상을 확인).
- 자리 결정은 화면에서 한다: 칸마다 후보(오른쪽·아래·위·반투명)를 숨겨서 그려 두고, 글자 맞춤 효과가 "바닥 크기에서도 넘침"이라고 판단한 칸만 첫 후보를 켜고 글자를 스티커 없이 다시 맞춘다. 스티커가 없는 칸은 기존 동작이 그대로다. 이웃 칸에 나온 스티커는 그 칸 폭을 넘지 않게 자른다(옆 상품 칸을 덮지 않기 위해).
- 측정(테스트 DB 11/16, 칠판 크기 1280×720, 줄 18px·35줄, 스티커 39칸 = 이 화면 칸의 46%로 실제보다 훨씬 촘촘): 칸 안 29 · 반투명 5 · 아래 3 · 위 1 · 오른쪽 1. 칸 안에 들어간 29칸 중 27칸에서 상품 수량 글자가 스티커 없을 때보다 작아졌다(1px 22칸·2px 2칸·3px 2칸·4px 1칸, 대부분 11px→10px). 칸 안 스티커 글자는 6~7px.
- 글자 잘림 점검 3종: 모니터 1·2는 모두 위반 0. 전체보기는 잘림 14건·세로 중앙 1건(스티커 없는 날짜의 대조군은 잘림 5건·세로 중앙 0). 스티커 칸에서 나온 3건은 모두 스크롤 가장자리에 걸린 것(확인한 2건은 오른쪽·아래 경계 밖)이고 세로 중앙 1건은 위·아래 여백 차이 1.0px로 경계값이다.

## 알려진 위험
- 바닥(7px)까지 글자가 줄어든 칸이 얼마나 되는지는 실제 데이터로 재야 안다(PR 2). 스티커가 있는 칸만 글자가 작아 보일 수 있다.
- 칠판의 터치·펜 동작은 PC에서 재현되지 않는다. PR 3a·3b는 배포 뒤 칠판 확인이 있어야 "문제 없음"이라 말할 수 있다.

## PR 3b 구현 메모 (2026-11-22): 칠판에서 스티커 붙이기
- **진입**: 도구 묶음의 네 번째 버튼(스티커). 모니터 1·2를 그리는 기기(`inkWriter`)에만 있다(별도 주문 팝업은 제외). 켜면 펜·지우개가 꺼지고, 펜을 켜면 스티커 모드가 꺼진다. 별도 주문 팝업을 열 때도 꺼진다.
- **흐름**: 아래 띠에서 스티커를 고른다(처음엔 목록의 첫 번째) → 상품 칸 탭 → 수량을 쓰는 스티커는 칸 아래에 말풍선(**1~10은 누르는 즉시 붙고**, "11 이상"은 전체 키패드: 0은 맨 앞에 못 오고 최대 9999) · 안 쓰는 스티커는 탭하는 순간 붙는다. 붙인 뒤에도 같은 스티커가 선택돼 있다.
- **고치기·떼기**: 붙은 스티커를 탭하면 수량 바꾸기(1~10, 11 이상)·떼기 말풍선. 수량 없는 스티커는 떼기만. 이웃 칸으로 나온 스티커도 눌린다(배지의 실제 화면 위치로 판정, 2px 여유).
- **규칙**: 같은 스티커가 이미 붙은 칸을 탭하면 새로 붙이지 않고 그 스티커의 수정 말풍선이 뜬다. 칸에 2개가 차 있으면 안내("한 칸에는 스티커를 2개까지…"). 서버(`actions.ts`)와 DB(unique·트리거)가 같은 규칙을 한 번 더 막는다.
- **탭을 받는 방식**: 스티커 모드는 화면 전체를 덮는 투명 층(`sticker-layer.tsx`)이 탭을 받아 칸·배지를 위치로 찾는다. 층이 아래 표를 덮으므로 포장 완료 탭은 일어나지 않고(`readOnly`에도 스티커 모드를 포함했다), 끝내면 다시 정상으로 눌린다(테스트 DB에서 확인).
- **저장**: `addItemSticker`/`setItemStickerQuantity`/`removeItemSticker`(권한 `dashboard:edit`, 과거 날짜는 포장 체크와 같은 설정 규칙). 붙을 당시의 이름·색을 스티커 목록에서 복사해 저장한다. 화면은 서버 응답을 기다리지 않고 바로 보이고(`useOptimistic`), 실패하면 안내하고 원래대로 돌아온다.
- **실시간**: `order_item_stickers` 변경이 오면 다른 기기도 화면을 새로 받는다(소리는 없음). 삭제 신호는 기본키만 담아 어느 카드인지 몰라 항상 새로 받는다. 다른 기기에서 넣은 스티커가 새로고침 없이 약 2초 안에 보이는 것을 테스트 DB로 확인했다.
- **개발 서버 주의**: 브랜치를 오가며 작업하면 개발 서버가 낡은 CSS를 내보내 스티커 후보가 숨겨지지 않고 겹쳐 보일 수 있다(2026-11-22 겪음). 이상하면 `.next`를 지우고 다시 띄운다.
