# 2026-11-07 영수증 메뉴 분리

정산 한 화면에 판매내역·매입내역·그래프·영수증 목록이 모두 있어 특히 모바일에서 스크롤이 길었다. 영수증 목록을 별도 메뉴 "영수증"(`/receipts`)으로 뺀다.

| # | 결정 | 이유·대안 |
|---|---|---|
| 1 | 영수증 **만들기**는 정산 판매내역에서 줄을 골라 그대로 한다. 발행된 영수증의 목록·보기·공유·삭제는 영수증 메뉴. 발행 직후 패널에 영수증 메뉴 링크를 보여 준다(영수증 보기 권한이 있을 때). | 만들기는 판매내역의 선택·입력과 한 흐름이다. |
| 2 | 권한을 새로 만든다: `receipts:view`(메뉴 열기·보기·공유), `receipts:delete`(삭제). 발행은 `settlement:edit` 그대로. 마이그레이션 0049가 기존 사용자에게 같은 범위로 옮겨 준다(정산 보기 → 영수증 보기, 정산 입력 → 영수증 삭제). | 사용자가 새 권한 신설을 선택했다. 대안(정산 권한 재사용)은 영수증만 따로 줄 수 없다. |
| 3 | RLS: `settlement_receipts` select는 `receipts:view` 또는 `settlement:view`(정산 화면이 "이미 발행됨" 경고에 읽는다), delete는 `receipts:delete`. `seller_businesses` select에 `receipts:view`를 더한다(영수증을 다시 열 때 직인을 읽는다). | 메뉴 권한과 DB 권한이 어긋나지 않게 한다. |
| 4 | 기간(일·주·월) 선택 줄은 정산의 `PeriodBar`를 `basePath`로 재사용하고, 기간 읽기는 `parsePeriodParams`(src/lib/settlement/url.ts)로 한 곳에 모았다. | 두 화면의 기간 규칙이 갈라지지 않게 한다. |

적용 순서: **0049를 먼저 적용한 뒤 배포**한다(반대면 새 메뉴가 권한 없이 열린다). 정산의 구역이 판매내역·매입내역·그래프 셋으로 줄었다.
