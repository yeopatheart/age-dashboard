# 2026-11-07 정산 판매내역 품목·수량 수정

판매내역의 품목·수량·단위는 주문 목록에서 가져오는데, 실제 출고·정산 값이 다를 때 정산에서 고칠 수 있게 한다.

| # | 결정 | 이유·대안 |
|---|---|---|
| 1 | 주문 목록 원본은 건드리지 않고 `settlement_sales.product_override`·`quantity_override`·`unit_override`(0048)에만 저장한다. null이면 원본을 쓴다. | 이미 포장·상차된 주문의 기록이 사후에 달라지는 것을 막는다. 대안(주문 목록도 같이 수정)은 사용자가 정산 전용을 선택했다. |
| 2 | 고친 줄은 노란 칸 + ↺ 버튼(품목·수량·단위를 한 번에 원래대로). 입력값이 원본과 같아지면 override를 지운다(null). | 원본으로 돌아간 줄이 "수정됨"으로 남지 않게 한다. |
| 3 | 매입내역 행(출고일 × 품목)·영수증 발행·그래프는 고친 값을 따른다(`SalesRow.product/quantity/unit`은 항상 고친 값, 원본은 `original`). | 한 곳에서 값을 정해 모든 화면이 같게 한다. |
| 4 | 품목명을 바꾸면 매입내역에 새 이름의 행이 따로 생긴다. 이전 이름으로 입력한 매입가가 있으면 그 행은 남는다(입력한 행은 판매내역에 없어도 보여 준다는 기존 규칙). | 매입가를 자동으로 옮기면 잘못 합쳐질 수 있어 옮기지 않고, 이름을 바꿀 때 안내 문구를 보여 준다. |
| 5 | 수량은 0 초과 100,000 이하, 소수 둘째 자리까지. 품목명 60자, 단위 10자(DB check와 server action 검증이 같다). | |

로직은 `src/lib/settlement/sales-edit.ts`(순수 함수, 테스트 포함). 마이그레이션 0048이 없으면 정산 화면은 `MigrationNotice`로 안내한다.
