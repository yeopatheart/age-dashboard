# 모바일 화면 (2026-10-29)

## 배경
주문 관리자는 출근 뒤에는 PC를 쓸 수 없고 개인 휴대폰으로 모니터링·업무 지시를 한다. 가장 중요한 메뉴는 주문 입력과 대시보드. PC 화면은 그대로 두고 휴대폰에서만 다르게 보인다.

## 조사 결과(근거 수준: 공식 도움말·스토어 설명·UX 글, 화면 구조 직접 확인은 일부만)
- 많은 행 × 많은 항목은 가로 스크롤 표가 아니라 **행 = 카드, 카드 안에 진행률·예외 요약, 상세는 펼침/하단 시트**가 정석(Odoo 모바일 피킹의 "n/m + 완료 초록", Uber Eats·배민 사장님의 신규/진행 구분, 모바일 표 설계 글의 "스캔이 목적이면 카드, 비교가 목적이면 첫 열 고정").
- 상단 요약은 스크롤해도 보여야 한다(Airtable iOS에서 요약 바가 없어 불만이 나온 사례). Shopify의 기본 "미처리" 뷰처럼 기본 필터는 "미완료".
- 터치 영역 44pt(Apple)/48dp(Material), 입력 글자 16px 이상(iOS 자동 확대 방지), 하단 고정 바는 safe-area.

## 결정
- **모바일 전용 화면을 새로 만든다**(768px 이하, `dashboard-mobile.tsx`). PC 컴포넌트에 반응형을 섞지 않아 PC가 깨질 위험이 없다. 데이터·서버 기능·권한은 PC와 공유하고, 모달·확인창도 같이 쓴다. 서버가 User-Agent로 처음부터 맞는 화면을 그려 PC 화면이 깜빡이지 않게 하고, 브라우저가 폭으로 다시 확정한다.
- 모바일 대시보드: 고객 카드 리스트(접힘 요약 한 줄 + 예외 배지 + 진행률), 고정 진행 요약·상태 필터(기본 미완료), 터미널 칩(필터), 별도 주문 전환, 품목별 수량 보기, 상품 탭 → 하단 시트(포장 체크·수정·미출고·취소·삭제). 순서 드래그는 모바일에서 쓰지 않는다.
- **모바일에서 할 수 있는 일은 보기 + 수정·지시**(권한이 없으면 자동으로 보기만).
- 휴대폰 하단 탭(대시보드·주문 목록·주문 입력·상차 스캔·더보기, 권한 있는 메뉴만. 박스 할당은 더보기에서 연다 — 2026-11-06 확인: 현장에서 가장 많이 쓰는 포장 체크(주문 목록)와 상차 스캔을 탭에 두기로 하고 문서를 코드에 맞췄다), 홈 화면에 앱처럼 추가(PWA manifest·아이콘·iOS meta), `viewport-fit=cover`와 safe-area, 입력 16px.
- 푸시 알림(새 주문 알림)은 서버 구성이 따로 필요해 이번 범위에서 뺐다.

## 진행 순서
1. 하단 탭 + PWA + 대시보드(이 결정)
2. 주문 입력 모바일(큰 입력칸 → 줄별 검토 카드 → 하단 고정 확정 버튼)
3. 박스 할당·상차 스캔 등 나머지 메뉴의 휴대폰 점검

## 휴대폰 UI 규칙 (통일 기준)
버튼·입력·칩 크기와 글자가 메뉴마다 제각각이던 것을 한 규칙으로 맞췄다(`globals.css` 토큰).
- 글자: html 14px(2026-11-07에 14.5→14px: 형이 주로 쓰고 "모바일은 글자가 클 필요 없다"는 요청, 표 본문 0.875rem·구역 제목 1rem으로 한 단계씩 축소, 정산 표의 선택칸은 표 글자와 같게, 날짜 선택은 글자를 작게 보이고 투명 입력칸을 겹침) 기준 본문 0.875rem, 보조 0.75rem, 제목 1.1875rem, 버튼·칩 0.8125rem 굵게. 입력·선택칸 글자는 `--input-fs` = **16px**이다(2026-11-06 변경). 처음(2026-10-29)에는 입력칸 글자가 다른 글자보다 커 보인다는 지적으로 버튼·칩과 같은 0.8125rem(약 11.8px)으로 맞추고 viewport `maximum-scale=1`로 iOS 자동 확대를 막았으나, UI 감사에서 이동 중·야외에서 읽기 어렵고 핀치 확대가 막힌다는 점이 문제로 나와 입력칸만 16px로 올리고 `maximum-scale`을 뺐다. 입력칸이 어색하게 커 보이면 `--input-fs`를 줄이는 대신, 입력칸에만 적용하는 값이라 버튼·칩 글자(0.8125rem)는 그대로라는 점을 감안해 다시 판단한다.
- 높이: 일반 컨트롤 36px, 칩·태그 32px, 한 번에 확정하는 주 동작(시트 버튼·라벨 출력) 48px. 이전 44px는 정보 밀도가 낮아 줄였다(Apple 44pt·Material 48dp 권장보다 작으므로, 오터치가 잦으면 다시 키울 값이다).
- 모양: 컨트롤은 알약, 카드 모서리 14px. 메뉴 설명은 숨긴다.
- 화면별: 대시보드는 위에서 날짜·터미널 칩·진행·상태 필터가 약 130px(진행+상태 필터만 고정), 리포트는 기간 종류 → 기간 이동 → 보기 → 정렬·CSV 순으로 줄마다 폭을 채움, 주문 입력은 제목 아래 한 줄에 날짜 이동 + 1·2차, 입력 가이드 버튼은 숨김.

## 2026-11-07 날짜·구분 컨트롤 통일
날짜 선택이 화면마다 달랐다(공용 DateNav · 정산/영수증 PeriodBar · 리포트 period-card · 주문 목록 모바일 dm-date · PC 주문 목록 tailwind) — 모양·크기·글자·"오늘" 동작이 모두 제각각이었다. 구분 선택도 같은 문제였다(ov-seg · 리포트 seg · dm-toggle · dm-seg · round-toggle).
- **DateNav/PeriodNav**(`components/date-nav.tsx`): [‹] [날짜 알약] [›] [오늘]. 알약(999px), 높이 `--ctl-h`(휴대폰 `--chip-h`), 글자 0.8125rem 굵게, "오늘"은 오늘이 아닐 때만 채운 색으로. 날짜 알약은 글자만 보이고 진짜 날짜 입력칸을 투명하게 겹친다(16px라 iOS 확대 없음, PC는 showPicker). 날짜 표기는 `2026.11.07`로 모든 화면 같다.
- **Segmented**(`components/segmented.tsx`): 붙은 알약 묶음, 선택은 `--primary` 채움. Link(주소 이동)·버튼 모두 지원.
- 적용: 대시보드·박스 할당·주문 입력·주문 목록(모바일)·정산·영수증·리포트. 모양(`.dn-*`·`.sg-*`)은 globals.css 한 곳.
- **그대로 둔 것**: PC 주문 목록의 날짜 선택(tailwind, 표 화면 UI 유지 요청이 있었다). 필터 칩(터미널·상태 칩 등)은 날짜·구분 컨트롤이 아니라 따로 정리 대상이다.

## 2026-11-07 입력칸 글자·확대 제한 (2차)
입력·선택칸을 표 본문·필터 글자와 같은 크기로 통일해 달라는 요청으로 `--input-fs`를 16px에서 본문(md) 기준으로 바꾸고(도구줄 sm·표 md로 덮어씀), iOS 자동 확대는 viewport `maximum-scale=1`로 막았다(11/6의 "maximum-scale 제거"를 되돌림). 영향: 안드로이드 크롬 핀치 확대 제한(iOS는 무관). 되돌리려면 layout.tsx의 `maximumScale`을 지우고 `--input-fs`를 16px로.

## 2026-11-08 홈 화면·브라우저 아이콘
- 홈 화면 아이콘은 이미 로고다: iPhone은 `<link rel="apple-touch-icon">`(public/icons/apple-touch-icon.png 180px), Android(갤럭시 포함)는 manifest의 192·512·maskable 아이콘. 이미 홈 화면에 추가해 둔 단축 아이콘은 기기가 그때 받은 이미지를 기억하므로 바뀌지 않는다 — 지우고 다시 추가해야 새 아이콘이 보인다.
- 브라우저 탭·즐겨찾기 아이콘(`src/app/favicon.ico`)이 프로젝트 생성 때의 기본 이미지로 남아 있어 로고(icon-512를 가운데 86%로 잘라 16·32·48·64px)로 교체했다.
