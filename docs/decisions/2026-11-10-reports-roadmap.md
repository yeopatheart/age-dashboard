# 2026-11-10 리포트 고도화 방향

전체 기능이 어느 정도 구현된 시점에, 운영 데이터를 모니터링하고 시스템·프로세스를 개선하는 데 쓰는 리포트 체계를 정한다. 현재 `/reports`는 수량 표 3종(상품/업체/터미널)과 CSV뿐이고 차트가 없다.

## 결정 (사용자 확정)
- 리포트 메뉴 아래에 탭 4개를 둔다. 합쳐서 보는 편이 효율적인 것은 합쳤다.
  1. **박스** = 박스 사용량 + 추천 정확도(주간 추이, 신뢰도·박스 수·업체·박스 종류·상품 포함 여부별, "어떤 경우에 떨어지는지"는 추천 vs 실제를 박스 종류가 다름 / 개수가 다름 / 배치만 다름으로 분류).
  2. **운영 시간** = 단계별(박스 할당 → 라벨 출력 → 포장 → 상차) 하루 구간(첫~마지막 이벤트)과 카드 단위 리드타임, 터미널별 상차 완료 시각.
  3. **판매·수익** = 기간별 품목·업체 판매수량·매출, 품목별 이익. 정산 화면의 그래프를 이쪽으로 옮기고 정산 화면에서는 뺀다. 기존 수량 표 3종은 "주문 수량" 보기로 흡수한다.
  4. **운영 개선** = 미출고 분석(사유별·품목별), 정산 마감 지연(판매가·매입가 미입력), 주문 입력 품질(`needs_review`·AI 보정 비율), 라벨 재출력률·스캔 되돌리기.
- **소요 시간은 리드타임으로 잰다.** 작업 시작 시각이 저장되지 않아 작업 자체의 소요 시간은 알 수 없다. 시작 버튼은 현장 작업자의 동작을 늘리므로 넣지 않는다(필요해지면 따로 설계).
- **금액 지표(매출·매입·이익)는 정산 보기 권한이 있을 때만 보인다.** `reports:view`만 있는 사용자는 수량·시간·박스 리포트만 본다(정산 권한 정책과 일치).
- **업체별은 매출만 보여 주고, 이익은 품목별로만 본다.** 매입이 (출고일 × 상품명) 단위라서 고객사별 이익은 직접 계산할 수 없다. 안분 추정치는 만들지 않는다.
- **재고·발주 알림은 이번 개편 밖이다.** 재고·단가·발주 데이터가 아예 없어 데이터 모델부터 새로 설계해야 한다. 박스 탭의 사용량(소진 속도)이 그 입력이 된다.
- 집계는 서버에서 하고 계산은 순수 함수로 분리해 단위 테스트를 붙인다. 차트는 recharts(이미 있음).
- PR 순서: **R0 수집 보강 → 박스 → 운영 시간 → 판매·수익 → 운영 개선.** 한 번에 하나씩 올리고 각각 운영에서 확인한 뒤 다음으로 간다.

## R0 수집 보강 (이 PR, 마이그레이션 0055)
기록이 안 남으면 나중에 소급해서 볼 수 없으므로, 리포트보다 먼저 두 가지를 남기기 시작한다.
- **박스 할당 제출 이력** `packing_submit_events`: 제출할 때마다 한 줄. 지금은 재제출하면 `packing_records`를 지우고 다시 만들어 재제출 횟수·최초 제출 시각·최초 제출 때의 추천 적중 여부가 사라진다. 업체명·터미널명은 복사해 두고(FK set null) 주문 카드가 지워져도 이력이 남는다. 신뢰도는 `recommendation_id`로 `packing_recommendations`에서 읽는다(중복 저장하지 않음).
  - 이력 저장이 실패해도 현장 제출은 막지 않는다. 서버 로그에만 남기고, 마이그레이션 전(테이블 없음)에는 조용히 건너뛴다.
- **AI 보정 여부** `order_items.ai_repaired`: AI가 형식을 벗어난 줄을 재구성한 줄이면 true. `needs_review`는 파서 불확실·수량 누락과 섞여 있다. 값은 true일 때만 쓴다 — 마이그레이션 전에도 일반 줄 입력이 막히지 않고, 한 번 AI 보정이면 그 기록을 지우지 않는다.

## 한계 (데이터가 없어 리포트로 못 하는 것)
- 박스 할당 시작·카드 단위 포장 완료·출고 완료 시각, 단계 전환 로그는 저장되지 않아 마지막 이벤트로만 유도한다.
- 주문 변경·취소 이력은 없다(`change_status`는 현재 상태 하나). 원래 수량과 변경 수량 비교는 불가.
- 판매가·매입가 변경 이력은 없다(덮어쓰기). 수정자(updated_by)는 어느 테이블에도 없다.
- 수량 단위(미/kg/팩/개)가 섞여 있어 품목 수량·단가는 단위별로 나눠 본다. 매입에는 수량이 없어 매입 단가는 계산할 수 없다.
- 박스 수 소스가 둘이다: `daily_businesses.total_boxes`(기존 리포트가 사용)와 `packing_boxes` 행 수. 박스 탭은 후자를 쓴다.
