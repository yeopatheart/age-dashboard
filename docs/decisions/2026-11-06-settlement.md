# 2026-11-06 정산 메뉴 설계 결정

요구사항·설계는 `docs/prd/settlement.md`. 아래는 사용자와 정한 갈림길과 이유다.

| # | 결정 | 이유·대안 |
|---|---|---|
| 1 | 매입내역 행은 **출고일 × 품목**으로 한 행. 주·월 조회에서는 출고일 열을 더한다. | 매입은 날마다 따로 하므로 매입가도 날짜별로 입력하는 편이 자연스럽다. 기간 합산 한 행은 어느 날의 매입가인지 정할 수 없어 입력이 모호하다. |
| 2 | 매입가가 비어 있는 행은 수익을 '-'로 두고 총 수익에서 제외하며 "매입가 미입력 N건"을 보여준다. | 0으로 보면 입력 전에는 수익이 판매가 전액으로 부풀어 보인다. |
| 3 | 그래프는 **recharts를 추가**해서 그린다(4단계). | 직접 SVG는 의존성이 없지만 사용자가 라이브러리 방식을 골랐다. 추가 전에 React 19·Next 16과의 호환(peerDependencies)을 확인한다. |
| 4 | 일 조회는 선택한 하루만 보여주되 추이 대신 **판매가·매입가·수익을 나란히 비교하는 막대 그래프**로 달리한다. 주·월은 일별 선 그래프. | 하루만으로는 추이가 안 보이므로 일 조회는 같은 날의 세 값 비교가 더 의미 있다. |
| 5 | 정산·사업자 관리는 **master만 기본으로 본다.** 필요한 사용자는 권한 화면에서 켠다. | 매입가·수익은 민감한 정보라 자동 부여 마이그레이션을 두지 않는다(0037 방식과 다르게). |
| 6 | 품목 기준은 **상품명**. | 매입처를 상품 단위로 등록하므로 같은 기준을 쓴다. 사이즈별 매입가를 나누고 싶어지면 그때 재검토한다. |

## 구조 결정(제안으로 진행)
- 판매내역은 출고 완료 카드의 주문 줄에서 읽을 때 계산하고, 입력값만 `settlement_sales`에 저장한다(주문이 바뀌어도 수량이 항상 맞는다).
- 매입내역은 사용자가 "이미 추가된 품목은 유지"를 요구해서 처음 나타날 때 한 번 저장하고 자동으로 지우지 않는다.
- 출고 완료 판정은 대시보드와 같은 `stageOf`를 그대로 쓴다(정의가 어긋나지 않게).
